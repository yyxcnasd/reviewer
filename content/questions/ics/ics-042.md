单精度浮点数有 24 位有效位（含隐含的 1），默认舍入方式为「就近舍入、平局取偶」。考虑下面的 C 代码：

```c
float a = 16777216.0f;   /* 2^24 */
float b = 1.0f;
float c = 1.0f;

float s1 = (a + b) + c;
float s2 = a + (b + c);
```

回答：

(1) 求 `s1` 与 `s2` 的值（用十进制和 \(2\) 的幂表示）；

(2) 说明第 (1) 问里每一次加法的舍入过程：为什么 \(2^{24}+1\) 会被舍掉；

(3) 若用一个 `float` 累加器从 \(0\) 开始顺序累加 \(10^8\) 个 `1.0f`，最终结果是多少？与精确值 \(10^8\) 相差多少？

(4) 编译器在 `-O2` 下能否把 `s1` 的算法改写成 `s2`（或对浮点求和循环做向量化重排）？默认为什么不行？`-ffast-math` 之后呢？

## 提示

先确定 \(2^{24}\) 落在哪个二进制区间：\(2^{24}\le x<2^{25}\)，区间内相邻可表示数的间距（ulp）是 \(2^{24-23}=2\)。

\(2^{24}+1\) 正好是两个相邻可表示数的中点，这时按「平局取偶」裁决：看尾数最低位是偶还是奇。

第 (3) 问不要硬算，想想累加器一旦到达 \(2^{24}\)，再加 \(1\) 会发生什么。

## 解析

**(1)** \(a=2^{24}=16777216\)。在区间 \([2^{24},2^{25})\) 内，ulp 为

\[
2^{24-23}=2,
\]

可表示的数只有 \(2^{24},\,2^{24}+2,\,2^{24}+4,\dots\)。

`a + b` 即 \(2^{24}+1\)，恰好是 \(2^{24}\) 与 \(2^{24}+2\) 的中点。平局取偶：\(2^{24}\) 的尾数整数部分是 \(2^{23}\)（偶），\(2^{24}+2\) 的是 \(2^{23}+1\)（奇），所以取偶数者，得 \(2^{24}\)。再 `+ c` 又是 \(2^{24}+1\)，同样舍回 \(2^{24}\)。因此

\[
s_1=2^{24}=16777216.
\]

`b + c` 是 \(1+1=2\)，精确；`a + 2` 即 \(2^{24}+2\)，正好是可表示数。因此

\[
s_2=2^{24}+2=16777218.
\]

两者不等，说明浮点加法**不满足结合律**。

**(2)** 关键的那一步是"先看区间、再算 ulp、最后处理平局"。舍入不是"丢掉小数"，而是在两个相邻可表示数之间二选一：距离不等取更近的，距离相等（中点）按 ties-to-even 取尾数为偶的那个。\(2^{24}+1\) 落在中点且 \(2^{24}\) 尾数更"偶"，所以被舍掉——不是"1 太小所以看不见"，而是"中点规则选了另一边"。

**(3)** 累加过程：

- 从 \(0\) 加到 \(2^{24}\) 期间，所有整数 \(<2^{24}\) 都能精确表示，累加器精确等于 \(2^{24}\)；
- 此后每次再加 \(1\)，和是 \(2^{24}+1\)，又落回中点，按平局取偶舍回 \(2^{24}\)；
- 所以累加器**卡在** \(2^{24}\) 不再增长，直到加完。

最终结果

\[
16777216,
\]

误差

\[
10^8-16777216=83222784,
\]

相对误差高达约 \(83\%\)。这就是"逐个累加大量小量"在浮点里不可靠的典型例子；工程上改用 `double` 累加、Kahan 求和或先排序再累加来缓解。

**(4)** 默认**不能**。因为 C 语言规定浮点运算按 IEEE 754 语义执行，编译器不得做会改变结果的代数变形；第 (1) 问已经给出反例：`(a+b)+c ≠ a+(b+c)`，重排会改变结果。同理，循环求和默认不能向量化重排（把 `((a0+a1)+a2)+…` 改成两两相加），否则结果可能不同。

`-ffast-math`（或 `-funsafe-math-optimizations`）允许编译器假定浮点满足结合律、忽略 NaN/Inf 等特殊值，从而可以重排、向量化以提速；代价是结果不再保证与逐条 IEEE 运算一致。这也是"科学计算不能随便开 -ffast-math"的原因。

## 常见错误

- 认为 \(2^{24}+1\) 存不下是因为"1 太小被丢掉"。真正原因是它落在两个可表示数的中点，舍入规则做了裁决。
- 把 `s2` 也算成 \(2^{24}\)，忘了 \(b+c=2\) 先精确算出来，再加到 \(a\) 上正好是可表示数。
- 第 (3) 问按"每次误差都 ≤ ulp/2"估计，得出误差不超过 \(10^8\) 量级的小数；实际是系统性卡死，误差同阶于总和。
- 以为编译器"显然"可以做浮点重排优化。默认不允许，这正是 `-ffast-math` 存在的原因。
