两个源文件：

```c
/* util.c */
static int counter = 0;
int next(void) { return ++counter; }
```

```c
/* main.c */
#include <stdio.h>
int next(void);
int main(void) {
    printf("%d\n", next());
    return 0;
}
```

回答：

(1) 写出把这两个文件编译链接成可执行文件 `prog` 的命令序列，以及每一步的产物。

(2) `counter` 在目标文件的符号表里是什么链接属性？如果在 `main.c` 里写 `extern int counter;` 并访问它，会在哪一步、报什么错？

(3) 在 `main.o` 里，`call next` 这条指令的目标地址在汇编阶段是填不出来的。汇编器怎么处理它？链接器最终如何把地址算出来？

(4) 为什么 `.o` 文件不能直接运行，而必须经过链接、再由加载器装入内存？加载器在程序真正开始执行前做了哪些事？

## 提示

把「符号」和「地址」分开看：编译单元之间只知道符号名，不知道最终地址。`static` 决定符号是 local 还是 global；`call` 后面 4 字节的位移留着重定位记录；加载器负责把各段放到内存里并跳到入口。

## 解析

**(1)**

```
gcc -c util.c          # 预处理 + 编译 + 汇编 → util.o
gcc -c main.c          # 预处理 + 编译 + 汇编 → main.o
gcc main.o util.o -o prog   # 链接 → 可执行文件 prog
```

- `.o` 是可重定位目标文件：已有机器码，但地址是「相对本文件」的，符号还没最终定位；
- 可执行文件里，各段的虚拟地址、符号地址都已确定，还有程序入口。

**(2)** `counter` 前面有 `static`，是**内部链接（internal linkage）**，在符号表里标记为 `STB_LOCAL`，只在本编译单元内可见。

`next` 没有 `static`，是外部链接（`STB_GLOBAL`），别的目标文件可以通过符号 `next` 找到它。

如果 `main.c` 写 `extern int counter;` 并访问，编译器能通过编译（有声明），但生成的重定位记录指向符号 `counter`；链接时链接器在所有目标文件的**全局**符号表里找 `counter`，找不到（util.c 里它是 local 符号，不导出），于是报

```
undefined reference to `counter'
```

**(3)** 汇编器不知道 `next` 最终在哪个地址，所以先把它留成占位值（典型是 `call` 后的 4 字节位移填 0），同时在 `.rela.text` 段里记一条重定位项，例如

```
R_X86_64_PLT32   next - 0x4
```

意思是「这里要填的是符号 `next` 的地址，再减去 4（PC 相对寻址的修正）」。

链接器做符号解析：把所有目标文件和库的符号表合并，为每个全局符号分配最终地址。看到这条重定位记录，就计算

\[
\text{填入值}=S+A-P,
\]

其中 \(S\) 是 `next` 的最终地址，\(A\) 是加数（这里是 \(-4\)），\(P\) 是被重定位位置（`call` 指令中位移字段的地址）。填好之后，`call` 的 32 位相对位移才指向正确目标。

**(4)** `.o` 不能直接运行，原因有三：

1. **它没有程序入口**（没有 `_start`），操作系统不知道该从哪条指令开始；
2. **重定位还没完成**，`call`、全局变量访问都留着占位地址；
3. 它只是一个目标文件，标准库（如 `printf` 所在的 `libc`）还没接上。

链接之后生成可执行文件，操作系统加载器在启动程序时做这些事：

- 读取 ELF 头与程序头表，把代码段、只读数据段、数据段按虚拟地址映射进进程地址空间；
- 为 `.bss` 段分配零初始化内存；
- 建立用户栈，把 `argc`、`argv`、环境变量压到栈上；
- 若程序是动态链接的，先加载动态链接器，解析 `libc` 等共享库的符号；
- 跳到入口 `_start`，由 C 运行库初始化后调用 `main`。

而 `call` 后面的地址在单个 `.o` 里不可能知道，只能留重定位记录——两条线索都指向「链接器负责把名字变成地址」。

## 常见错误

一是以为 `gcc -c` 会完成链接，其实它只到汇编、产出 `.o`。二是把 `static` 理解成「只读」或「局部变量」，这里是**内部链接**，作用是符号不导出。三是认为 `extern int counter;` 能让 local 符号变成可见——链接器只看导出符号。四是把重定位说成「链接器重新编译代码」；它只是改地址字段，机器码本身不变。五是以为加载器会把整个文件原样读进内存执行，实际上它按段映射，`.bss` 不占文件空间。
