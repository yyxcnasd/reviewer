函数 `foo` 的汇编开头是

```
foo:
    pushq %rbp
    movq %rsp, %rbp
    subq $24, %rsp
    ...
    call bar
```

执行到 `foo` 的第一条指令之前，`%rsp = 0x7fffffffe018`（除以 \(16\) 余 \(8\)）。

回答：

(1) 执行完 `pushq %rbp`、`subq $24, %rsp` 后，`%rsp` 各是多少？

(2) 执行 `call bar` 之前，`%rsp` 是否满足 ABI 的 16 字节对齐要求？`bar` 刚进入时 `%rsp` 除以 \(16\) 余几？

(3) 如果 `bar` 中用 `movaps` 向按 16 字节对齐分配的栈槽写数据，可能发生什么？

(4) 只改 `subq` 的立即数，应该改成多少？并说明为什么进入 `foo` 时 `%rsp` 除以 \(16\) 余 \(8\)。

## 提示

ABI 要求执行 `call` 之前 `%rsp` 是 \(16\) 的倍数；`call` 会把 8 字节返回地址压栈，所以被调用函数刚进入时 `%rsp` 除以 \(16\) 余 \(8\)。`pushq` 减 8，`subq` 减立即数，按十六进制逐次算。

## 解析

**(1)** 起始

\[
\%rsp=\texttt{0x7fffffffe018}.
\]

`pushq %rbp` 减 8：

\[
\%rsp=\texttt{0x7fffffffe010}.
\]

`subq $24` 即减 \(\texttt{0x18}\)：

\[
\%rsp=\texttt{0x7fffffffe010}-\texttt{0x18}
=\texttt{0x7fffffffdff8}.
\]

**(2)** \(\texttt{0xdff8}\) 除以 \(16\) 余 \(8\)，不是 \(16\) 的倍数，所以**不满足** ABI 要求。执行 `call bar` 后，返回地址压栈，`%rsp` 再减 8：

\[
\texttt{0x7fffffffdff8}-8=\texttt{0x7fffffffdff0},
\]

它除以 \(16\) 余 \(0\)。而正常约定是被调用函数进入时余 \(8\)，所以 `bar` 一进来就已经错位了。

**(3)** 编译器生成 `bar` 的代码时，假定进入时 `%rsp` 余 \(8\)，于是按这个前提给局部变量分配 16 字节对齐的槽位。实际进入时余 \(0\)，所有基于 `%rsp` 的局部变量地址都会偏移 8 字节。`movaps` 要求内存操作数 16 字节对齐，一旦地址不对齐就会触发 general protection fault，在 Linux 上表现为段错误（SIGSEGV）。

**(4)** 要让 `call bar` 前 `%rsp` 是 \(16\) 的倍数，需要

\[
\texttt{0x7fffffffe010}-N\equiv0\pmod{16}.
\]

`0x...e010` 本身是 \(16\) 的倍数，所以 \(N\) 必须是 \(16\) 的倍数。同时局部变量需要至少 \(16\) 字节，因此取不小于需求的最小 \(16\) 的倍数：

```
subq $32, %rsp
```

这样 `%rsp = 0x7fffffffdff0`，`call` 后 `bar` 进入时 `%rsp = 0x7fffffffdff8`，余 \(8\)，恢复正常。

进入 `foo` 时余 \(8\) 的原因：调用者执行 `call foo` 前把 `%rsp` 保持为 \(16\) 的倍数，`call` 压入 8 字节返回地址，于是 `foo` 看到的就是「\(16\) 的倍数减 8」，即余 \(8\)。

结论：**(1) 依次为 `0x7fffffffe010`、`0x7fffffffdff8`；(2) 不满足，`bar` 进入时余 \(0\)；(3) `movaps` 会因地址未对齐触发异常（段错误）；(4) 改成 `subq $32, %rsp`；`call` 压入 8 字节返回地址，所以进入函数时余 \(8\)。**

## 常见错误

一是以为进入函数时 `%rsp` 是 \(16\) 的倍数，忘了 `call` 已经压过返回地址。二是算 `subq $24` 时把十进制 \(24\) 与十六进制 `0x24` 混淆。三是把对齐要求记成「`call` 前余 \(8\)」，正好说反。四是只把 `subq $24` 改成 `subq $16`：局部变量够不够是另一回事，`$16` 之后 `%rsp` 余 \(8\)，`call` 前仍然不对齐。五是认为 `movaps` 和普通 `mov` 一样，未对齐也能执行。
