下面是调用者 `caller` 中为调用 `f` 准备参数的汇编（`f` 的返回值在 `%rax`，调用者不使用）：

```
caller:
    subq  $24, %rsp
    movq  $9, 16(%rsp)
    movq  $8, 8(%rsp)
    movq  $7, (%rsp)
    movl  $6, %r9d
    movl  $5, %r8d
    movl  $4, %ecx
    movl  $3, %edx
    movl  $2, %esi
    movl  $1, %edi
    call  f
    addq  $24, %rsp
    ret
```

回答：

(1) 写出 `f` 的函数原型（参数类型用 `long`）以及这次调用的实参序列；

(2) 在 `f` 里，第 \(7\)、\(8\)、\(9\) 个参数分别相对 `%rbp` 的偏移是多少？写出 `f` 开头为读到这三个参数所需的典型序言；

(3) 为什么 `caller` 减的是 \(24\)？如果把 `subq $24` 改成 `subq $32`，会出什么问题？

(4) 如果只传 \(8\) 个参数（两个栈参数），`subq` 应该改成多少？为什么不是 \(16\)？

(5) 前 \(6\) 个参数按什么顺序使用寄存器？

## 提示

前 \(6\) 个整型/指针参数走寄存器，第 \(7\) 个起走栈。`call` 指令会压入 8 字节返回地址，所以被调用者刚进入时 `%rsp` 余 8；ABI 要求**执行 `call` 之前**调用者的 `%rsp` 是 16 的倍数。

先算出"进入 caller 时 `%rsp` 余 8"，再要求"减去 \(N\) 后余 0"：\(8-N\equiv0\pmod{16}\)，即 \(N\equiv8\pmod{16}\)。

## 解析

**(1)** 六个寄存器参数 + 三个栈参数，共 \(9\) 个 `long`：

```c
long f(long a, long b, long c, long d, long e, long g,
       long h, long i, long j);
```

这次调用的实参依次是 \(1,2,3,4,5,6,7,8,9\)：寄存器拿到前 \(6\) 个，栈上从低到高放 \(7,8,9\)。

**(2)** `caller` 在 `call` 之前把三个栈参数放在 `0(%rsp)`、`8(%rsp)`、`16(%rsp)`。`call f` 压入 8 字节返回地址，`f` 再执行 `pushq %rbp`，于是

\[
\%rbp=\%rsp_{\text{call 前}}-8-8,
\]

第 \(7\) 个参数在 `%rbp+16`，第 \(8\) 个在 `%rbp+24`，第 \(9\) 个在 `%rbp+32`。典型序言：

```
f:
    pushq %rbp
    movq  %rsp, %rbp
    movq  16(%rbp), %rax   # 第 7 个参数
    movq  24(%rbp), %rcx   # 第 8 个
    movq  32(%rbp), %rdx   # 第 9 个
    ...
```

注意：`0(%rbp)` 是保存的旧 `%rbp`，`8(%rbp)` 是返回地址，**不能**把 `8(%rbp)` 当第一个栈参数——这是最常错的一位偏移。

**(3)** 三个栈参数占 \(3\times8=24\) 字节。再看对齐：设进入 `caller` 时

\[
\%rsp\equiv 8\pmod{16},
\]

执行 `call f` 之前要求 `%rsp` 是 16 的倍数，所以减去的 \(N\) 要满足

\[
8-N\equiv0\pmod{16}\quad\Longrightarrow\quad N\equiv8\pmod{16}.
\]

\(N=24\) 恰好既够放三个参数（\(24\) 字节），又满足 \(24\equiv8\pmod{16}\)：

\[
8-24=-16\equiv0\pmod{16}.
\]

所以 \(24\) 是"够用且对齐"的最小值。不要只算"参数需要多少字节"，还要算"减完后 `%rsp` 余几"。

若改成 `subq $32`：参数放得下，但

\[
8-32=-24\equiv8\pmod{16},
\]

`call f` 前 `%rsp` 不是 16 的倍数，被调用者进入时 `%rsp` 余 0（而约定是余 8），一旦 `f` 内部用了要求对齐的 SSE 指令（如 `movaps`）就会崩溃，或者局部变量取到错位数据。

**(4)** 两个栈参数占 \(16\) 字节，\(16\not\equiv8\pmod{16}\)，所以不能只减 \(16\)：那样 `8-16\equiv8`，不对齐。要满足 \(N\equiv8\pmod{16}\) 且 \(N\ge16\)，最小是 \(24\)（\(16\) 字节参数 + \(8\) 字节填充）。所以仍然写 `subq $24`，只是最后 \(8\) 字节是填充而不是参数。

**(5)** x86-64 System V 的整型/指针参数寄存器顺序是

\[
\%rdi,\ \%rsi,\ \%rdx,\ \%rcx,\ \%r8,\ \%r9,
\]

第 \(7\) 个及以后走栈（从低地址到高地址）。`%rax` 用于可变参数函数的向量寄存器个数，返回值也放 `%rax`。

## 常见错误

- 把栈参数的偏移算成 `0(%rbp)`、`8(%rbp)`、`16(%rbp)`，忽略保存的 `%rbp` 和返回地址各占 8 字节。
- 以为"参数占 24 字节，所以减 24 一定对"——恰好这题凑巧对，但换成两个栈参数（16 字节）就必须补 8 字节填充，规律是 \(N\equiv8\pmod{16}\)，不是"参数大小"。
- 把 `subq $32` 当成"凑成 16 的倍数所以没问题"。对齐要求的是 `call` 前 `%rsp` 模 16 为 0，而入口余 8，减 32 反而余 8。
- 认为参数从左到右压栈。System V 是寄存器优先；栈上参数等价于"从左到右、地址从低到高"。
- 忘记 `call` 本身会压返回地址，导致被调用者看到的栈偏移整体少 8。
