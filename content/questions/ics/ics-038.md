考虑递归函数

```c
long f(long n) {
    char buf[64];
    buf[0] = (char)n;
    if (n <= 1) return 1;
    return f(n - 1) + n;
}
```

它的汇编序言是

```
f:
    pushq %rbp
    movq  %rsp, %rbp
    subq  $72, %rsp
    ...
```

其中 `subq $72` 为 64 字节的 `buf` 和额外的 8 字节对齐空间。回答：

（1）每进入一层 `f`，栈上至少增加多少字节？

（2）调用 `f(100)` 时，递归深度（同时存在的 `f` 栈帧层数）是多少？

（3）从进入 `f(100)` 时的 `%rsp` 算起，递归最深时栈指针共向下移动多少字节？

（4）若进程可用的栈空间为 8 MiB（\(8\times2^{20}\) 字节），估算 \(n\) 最大约为多少时不会栈溢出。

## 提示

一层调用的真实开销不只 `sub` 的那部分：`call` 先压 8 字节返回地址，进入函数后又 `pushq %rbp`（8 字节），再 `subq $72`。把这三块加起来才是「一层」的字节数。递归深度等于从 \(n\) 递减到 \(1\) 的层数。

## 解析

**关键的那一步为什么能想到。** 递归栈溢出的计算关键是「每一层到底花多少栈」。容易只盯着局部数组 `buf` 的 64 字节，但调用本身还有两笔固定开销：`call` 压入的返回地址，以及 `pushq %rbp` 保存的旧帧指针。把这三笔加起来，再乘以层数，才是总占用。层数则由递归终止条件决定：从 \(n\) 一路减到 \(1\)，共 \(n\) 层。

（1）每层包含：
- `call` 压入的返回地址：8 字节；
- `pushq %rbp`：8 字节；
- `subq $72`：72 字节。

合计
\[
8+8+72=88\ \text{字节}.
\]

（2）`f(100)` 调用 `f(99)`，…，直到 `f(1)` 返回。同时存在的层是 \(n=100,99,\dots,1\)，共
\[
100\ \text{层}.
\]

（3）每层 88 字节，所以最深时栈指针下移
\[
100\times88=8800\ \text{字节}.
\]

（4）设最多 \(n\) 层，要求
\[
88n\le8\times2^{20}=8388608.
\]
计算
\[
n\le\frac{8388608}{88}\approx95325.1,
\]
所以
\[
n_{\max}=95325.
\]
可以验证：\(95325\times88=8388600\le8388608\)，而 \(95326\times88=8388688>8388608\)。实际系统还有环境变量、启动栈等占用，真实上限会比这个估算略小。

## 常见错误

一是只算 `subq $72`，漏掉 8 字节返回地址和 8 字节保存的 `%rbp`，每层少算 16 字节，总占用和 \(n_{\max}\) 都会偏差很大。二是把深度算成 \(n+1\)（把调用者自己的栈帧也算进去），或算成 \(n-1\)（漏掉最底层）。三是用 \(8\times10^{6}\) 代替 \(8\times2^{20}\) 做估算，边界值会差几千层。四是把 `buf[64]` 与 `subq $72` 混为一谈：72 里除了 64 字节数组还有 8 字节的对齐空间。
