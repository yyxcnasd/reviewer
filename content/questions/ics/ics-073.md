一台机器使用 **32 位地址**，数据 cache 是**直接映射**（direct-mapped）：容量 \(32\ \text{KB}\)、cache line \(64\ \text{B}\)。两个全局数组

```c
int A[8192];
int B[8192];     /* 位于 A 之后，B 的起始地址为 0x00408000 */
```

`A` 的起始地址是 `0x00400000`。考虑循环

```c
long s = 0;
for (int i = 0; i < 8192; i++)
    s += A[i] + B[i];
```

命中 \(1\) 个周期、缺失额外 \(100\) 个周期。

(1) 写出 32 位地址在直接映射 cache 中的 tag / index / offset 位域划分（各多少位），并算出 `A[0]`、`B[0]` 的 set index 与 tag。

(2) 分析这个循环的缺失率。为什么两个数组各占 \(32\ \text{KB}\)、cache 也正好 \(32\ \text{KB}\)，却每次访问都缺失？

(3) 把循环改成「每 16 个元素一组：先读完 `A` 的 16 个，再读 `B` 的 16 个」，估算新的缺失率、每次访问平均周期数与加速比。

(4) 若把 `B` 移到与 `A` 相距 \(16\ \text{KB}\) 的位置（起始 `0x00404000`），缺失率会变成多少？为什么？

(5) 若 cache 改成 8 路组相联（容量、line 不变），本题的冲突会消失吗？

## 提示

直接映射 cache 的地址拆法：低 \(\log_2 64=6\) 位是 line 内偏移，接着 \(\log_2 512=9\) 位是 set index（\(32\ \text{KB}/64\ \text{B}=512\) 行），剩下的高位是 tag。两个地址只要 index 相同、tag 不同，就会抢同一个 set。注意两个数组的起始地址相差 \(32\ \text{KB}\)，恰好是 cache 容量的整数倍。

## 解析

**(1)** 32 位地址拆成

\[
\begin{aligned}
\text{offset} &: \text{低 }6\text{ 位} &&(2^{6}=64\ \text{B/line})\\
\text{index}  &: \text{中间 }9\text{ 位} &&(2^{9}=512\ \text{set})\\
\text{tag}    &: \text{高 }17\text{ 位} &&(32-6-9=17)
\end{aligned}
\]

`A[0]` 的地址是 `0x00400000`：

\[
\begin{aligned}
\text{index}_{A} &= (0x00400000 \gg 6)\ \&\ 0x1FF = 0,\\
\text{tag}_{A} &= 0x00400000 \gg 15 = 0x80.
\end{aligned}
\]

`B[0]` 的地址是 `0x00408000`：

\[
\begin{aligned}
\text{index}_{B} &= (0x00408000 \gg 6)\ \&\ 0x1FF = 0,\\
\text{tag}_{B} &= 0x00408000 \gg 15 = 0x81.
\end{aligned}
\]

两者的 index 相同、tag 不同，所以**映射到同一个 set**。

**为什么想到**：直接映射里「index 决定放哪一行、tag 决定是不是同一个块」，两个地址相差 \(32\ \text{KB}=512\) 条 line，正好是 set 数 \(512\) 的整数倍，所以 index 必然相同——这是冲突缺失的典型构造。

**(2)** `A[i]` 与 `B[i]` 的地址相差 \(32\ \text{KB}\)，因此对每个 \(i\) 都映射到同一个 set：

\[
\begin{aligned}
\text{set}(A[i]) &= \left(\frac{i}{16}\right)\bmod 512,\\
\text{set}(B[i]) &= \left(\frac{i}{16}+512\right)\bmod 512
=\left(\frac{i}{16}\right)\bmod 512.
\end{aligned}
\]

（一个 line 装 \(64/4=16\) 个 `int`，所以 \(\lfloor i/16\rfloor\) 是 line 号。）

直接映射的一个 set 只有一行：读取 `B[i]` 会把 `A` 的 line 挤出去，下一次读 `A[i+1]` 又要重新取回来，如此往复。每一对访问都触发两次缺失，所以缺失率是

\[
100\%.
\]

**为什么想到**：顺序访问本身局部性很好（一行 16 个元素），但两个数组"抢同一个 set"把空间局部性完全破坏——判断冲突缺失要看 index 是否重复，而不是看数组大小。

**(3)** 按 16 个元素分组后，`A` 的一组 16 个 `int` 正好是**一条 line**：读 `A` 的 16 个元素只缺失 1 次，随后 15 次命中；再读 `B` 的对应 16 个元素，同样只缺失 1 次。于是每 32 次访问有 2 次缺失：

\[
\text{缺失率}=\frac{2}{32}=6.25\%.
\]

每次访问平均周期数

\[
1+0.0625\times100=7.25.
\]

总访问次数是 \(2\times8192=16384\)：

\[
\begin{aligned}
T_{\text{朴素}} &= 16384\times(1+100)=1\,654\,784,\\
T_{\text{分块}} &= 16384\times7.25=118\,784,\\
\text{加速比} &= \frac{1\,654\,784}{118\,784}\approx13.9.
\end{aligned}
\]

**为什么想到**：冲突的根源是「A、B 交替访问同一 set」；把同一数组的 16 个元素连续读完，就等于把「交替」变成「成批」，一批只付一次缺失。

**(4)** `B` 起始 `0x00404000`，与 `A` 相距 \(16\ \text{KB}=256\) 条 line：

\[
\begin{aligned}
\text{index}_{B} &= (0x00404000 \gg 6)\ \&\ 0x1FF = 0x100 = 256,\\
\text{index}_{A} &= 0.
\end{aligned}
\]

`B[i]` 的 set 是 \(\left(\lfloor i/16\rfloor+256\right)\bmod 512\)，与 `A[i]` 的 set 相差 256（模 512 后仍不同），所以两者**不再冲突**。每个 line 的 16 个元素连续用完，缺失率回到

\[
\frac{1}{16}=6.25\%.
\]

**为什么想到**：相距 \(16\ \text{KB}\) 只移动了 256 条 line，而 set 数有 512，index 只会错开一半，不会重合；相距 \(32\ \text{KB}\) 才会整数倍地"绕回"同一个 set。

**(5)** 会消失。8 路组相联意味着每个 set 能放 8 条 line，本题冲突只涉及 `A`、`B` 两条 line，远小于 8 路，两条可以同时驻留；缺失率回到约 \(6.25\%\)。换更大的相联度或用按 16 个元素分组，本质都是"让冲突的两条 line 不要互相踢出去"。

## 常见错误

一是只按数组总大小与 cache 容量比较（\(32\ \text{KB}\) vs \(32\ \text{KB}\)），得出"刚好装得下所以不缺失"的结论，忽略**直接映射的两个数组会映射到同一 set**。二是把 index 位数算错（用 \(32\ \text{KB}/64\ \text{B}=512\) 却取 10 位）。三是分块后把缺失率算成 \(1/16\) 而不是 \(2/32\)（两者数值相同，但要数清一次分块里 A、B 各缺一次）。四是认为"改成 16KB 间距"一定更好而说不出原因——要落到 index 相差 256 这个具体数字上。
