函数

```c
long f(long a, long b, long c, long d, long e, long g, long h, long i);
```

的汇编开头是

```
f:
    pushq %rbp
    movq %rsp, %rbp
    subq $32, %rsp
    ...
```

(1) 8 个参数分别通过什么传递？

(2) 若进入 `f` 时 `%rsp = 0x7fffffffe008`，求返回地址、第 7 个参数、第 8 个参数、保存的 `%rbp` 的地址；执行完 `pushq %rbp`、`movq %rsp, %rbp`、`subq $32, %rsp` 后，`%rbp` 与 `%rsp` 各是多少？

(3) `subq` 的立即数 32 是怎么定的？如果函数里有 4 个 `long` 局部变量并要调用其他函数，为什么这个数必须是 16 的倍数？

## 提示

先记住约定：前 6 个整型参数走寄存器，从第 7 个开始从右往左压栈；进入函数时，栈顶是返回地址。`pushq %rbp` 会把 `%rsp` 再减 8，所以「返回地址在 `8(%rbp)`」而不是 `0(%rbp)`。

## 解析

**(1)** System V AMD64 约定：6 个整型参数依次放在

`%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`，

即 \(a\)–\(g\) 中的前六个。第 7 个（\(h\)）和第 8 个（\(i\)）从右往左压栈，位于栈上。

**(2)** 进入函数时，栈顶 `0(%rsp)` 是返回地址，所以

\[
\text{返回地址}=0x7fffffffe008.
\]

第 7 个参数在 `8(%rsp)`，第 8 个在 `16(%rsp)`：

\[
\text{第 7 个参数}=0x7fffffffe010,\qquad \text{第 8 个参数}=0x7fffffffe018.
\]

`pushq %rbp` 把旧 `%rbp` 存到 `%rsp-8 = 0x7fffffffe000`，此时 `%rsp = 0x7fffffffe000`；`movq %rsp, %rbp` 后

\[
\%rbp=0x7fffffffe000.
\]

因此保存的旧 `%rbp` 在 `0(%rbp)`，返回地址在 `8(%rbp)`，第 7 个参数在 `16(%rbp)`，第 8 个在 `24(%rbp)`。最后 `subq $32, %rsp`：

\[
\%rsp=0x7fffffffe000-0x20=0x7fffffffdfe0.
\]

**(3)** 进入函数时 `%rsp % 16 = 8`（`call` 压了 8 字节返回地址）；`pushq %rbp` 后再减 8，变成 `%rsp % 16 = 0`。之后每次 `subq` 只要减的是 16 的倍数，`%rsp % 16 = 0` 就保持不变，于是调用下一个函数时 `call` 前仍满足 ABI 的 16 字节对齐。

4 个 `long` 局部变量需要 32 字节，正好是 16 的倍数，所以 `subq $32`。若需要 24 字节，就要取 32——「不小于需求的最小 16 的倍数」。

## 常见错误

一是把第 7 个参数写成 `0(%rsp)` 或 `8(%rbp)`——那是返回地址的位置。二是忘记 `pushq %rbp` 占掉 8 字节，于是把返回地址算到 `0(%rbp)`。三是把 8 个参数全算成寄存器传递（寄存器只有 6 个）。四是 `subq` 后忘记 `%rsp` 再减 32，或把 32 当成十进制以外的单位。
