一台机器有一级数据 cache，容量 \(32\ \text{KB}\)，cache line 为 \(64\ \text{B}\)；`int` 占 \(4\) 字节，二维数组按行优先存放：

```c
int A[1024][1024];
long sum = 0;
```

考虑两种遍历方式：

```c
/* 方式一：内层 j，行优先 */
for (int i = 0; i < 1024; i++)
    for (int j = 0; j < 1024; j++)
        sum += A[i][j];

/* 方式二：内层 i，列优先 */
for (int j = 0; j < 1024; j++)
    for (int i = 0; i < 1024; i++)
        sum += A[i][j];
```

(1) 分别估算两种方式的 cache 缺失率。

(2) 设每次命中花 \(1\) 个周期、每次缺失额外花 \(100\) 个周期，估算两种方式每个元素的平均周期数。

(3) 两种方式的总周期数之比是多少？

(4) 如何改写循环，使列优先的访问也能接近行优先的性能？说明理由。

## 提示

先算一条 cache line 能装几个 `int`：\(64/4=16\) 个。行优先时内层沿行前进，相邻 16 次访问落在同一条 line 上；列优先时内层沿列前进，地址每次跳 \(1024\times4=4096\) 字节，一步跨过 \(64\) 条 line。再看 cache 能不能装下这些 line。

## 解析

**(1)** 一条 cache line \(64\ \text{B}\)，装 \(64/4=16\) 个 `int`。

**方式一（行优先）**：内层 \(j\) 每次加 1，地址加 4 字节。连续 16 次访问落在同一条 line 里，只有第一次缺失，后 15 次命中。所以缺失率

\[
\frac{1}{16}=6.25\%.
\]

当前行只占 \(1024\times4=4\ \text{KB}=64\) 条 line，而 cache 有 \(32\ \text{KB}/64\ \text{B}=512\) 条 line，装得下一整行，下一行也不会把当前行挤掉。

**方式二（列优先）**：内层 \(i\) 每次加 1，地址加 \(1024\times4=4096\ \text{B}=64\) 条 line。也就是说每访问一个元素，`A[i][j]` 与下一个元素 `A[i+1][j]` 落在完全不同的 line 上。

一列有 \(1024\) 个元素，需要 \(1024\) 条不同的 line；而 cache 只有 \(512\) 条 line。等外层 \(j\) 加 1、回到同一批元素附近时，早先的 line 已经被挤出 cache。所以几乎每次访问都缺失，缺失率接近

\[
100\%.
\]

**(2)** 平均周期数 = 命中时间 + 缺失率 × 缺失代价。

方式一：

\[
1+0.0625\times100=1+6.25=7.25\ \text{周期/元素}.
\]

方式二：

\[
1+1\times100=101\ \text{周期/元素}.
\]

**(3)** 数组共 \(1024\times1024=1\,048\,576\) 个元素。

\[
\frac{101}{7.25}\approx13.9.
\]

方式二比方式一慢约 \(13.9\) 倍。两者的指令数几乎一样，差距全来自**空间局部性**：行优先把一条 line 的 16 个元素用满了，列优先每个元素都要重新搬一条 line。

**(4)** 用**分块（blocking）**：每次只处理 \(16\times16\) 的子块，块内按行访问。

```c
for (int ii = 0; ii < 1024; ii += 16)
    for (int jj = 0; jj < 1024; jj += 16)
        for (int i = ii; i < ii + 16; i++)
            for (int j = jj; j < jj + 16; j++)
                sum += A[i][j];
```

这样内层 \(j\) 的 16 次访问正好落在一条 cache line（\(16\times4=64\ \text{B}\)）内；一个块只有 \(16\) 条 line，完全装得进 512 条 line 的 cache，下一次用到时还在。缺失率回到约 \(1/16\)，每个元素约 \(7.25\) 个周期。

## 常见错误

一是把列优先的缺失率估成 \(1/16\)——它每次访问都在不同的 line 上，根本没有复用。二是忘记用「工作集 \(1024\) 条 line 与 cache \(512\) 条 line」比较，只看到 line 大小就下结论。三是把两种方式的总周期比算成 \(100/1=100\)，忽略了命中时的 1 个周期。四是分块时取的块大小与 line 不匹配（比如取 \(8\times8\)），那样内层只用到半条 line，收益减半。
