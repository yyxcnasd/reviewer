`g` 是外部函数，参数和返回值都是 `long`。`f` 在 `-O0` 下的汇编如下：

```
f:
    pushq %rbp
    movq %rsp, %rbp
    pushq %rbx
    subq $24, %rsp
    movq %rdi, %rbx
    movq %rdi, -32(%rbp)
    call g
    movq %rax, -24(%rbp)
    movq -32(%rbp), %rax
    addq -24(%rbp), %rax
    addq $24, %rsp
    popq %rbx
    popq %rbp
    ret
```

回答：

(1) 还原 `f` 的 C 代码。

(2) 局部变量区（从 `-32(%rbp)` 到 `-9(%rbp)`）共多少字节？其中数组占多少、填充占多少？

(3) 若 \(g(x)=x+3\)，求 `f(7)`。

(4) 如果删掉 `pushq %rbx` 和 `popq %rbx`，会出什么问题？

(5) 为什么 `subq` 是 `$24` 而不是 `$16`？

## 提示

`-32(%rbp)` 是数组首地址，`-24(%rbp)` 是它的第二个 `long`。`%rbx` 是被调用者保存寄存器，用来跨 `call` 保存参数。局部变量区大小既要容纳数据，也要保证 `call g` 之前 `%rsp` 对齐。

## 解析

**(1)** 逐段翻译：

- `movq %rdi, %rbx` 把参数 \(x\) 存到 `%rbx`；
- `movq %rdi, -32(%rbp)` 把 \(x\) 存进数组第一个元素 `buf[0]`；
- `call g` 调用 \(g(x)\)，返回值在 `%rax`；
- `movq %rax, -24(%rbp)` 把结果存进 `buf[1]`；
- 最后把 `buf[0]`、`buf[1]` 相加返回。

所以

```c
long f(long x) {
    long buf[2];
    buf[0] = x;
    buf[1] = g(x);
    return buf[0] + buf[1];
}
```

**(2)** `buf` 是两个 `long`，占 \(2\times8=16\) 字节，地址从 `-32(%rbp)` 到 `-17(%rbp)`。局部变量区从 `-32(%rbp)` 到 `-9(%rbp)`，共

\[
32-8=24\ \text{字节}.
\]

其中数组占 \(16\) 字节，剩下的 `-16(%rbp)` 到 `-9(%rbp)` 是 \(8\) 字节填充。

**(3)** `f(7)` 中 `buf[0]=7`，`buf[1]=g(7)=10`，返回

\[
7+10=17.
\]

**(4)** `%rbx` 是**被调用者保存**寄存器，函数如果要用它，必须先保存旧值、返回前恢复。删掉 `pushq %rbx` 和 `popq %rbx` 有两个后果：

1. `call g` 之后，`g` 可以随意改写 `%rbx`，`f` 再读 `%rbx` 就拿到错误的值（本题中 \(x\) 丢失，返回值错误）；
2. `f` 自己违反了调用约定，返回后调用者的 `%rbx` 已被破坏，可能连锁导致上层函数算错。

**(5)** 进入 `f` 时 `%rsp` 除以 \(16\) 余 \(8\)；`pushq %rbp` 后余 \(0\)；`pushq %rbx` 后余 \(8\)。若只 `subq $16`，`%rsp` 仍余 \(8\)，`call g` 前不满足 16 字节对齐。取 \(24\)（\(16\) 字节数组加 \(8\) 字节填充）后，

\[
8-24\equiv0\pmod{16},
\]

`%rsp` 恢复对齐，`call g` 时被调用者进入的约定才正确。所以 \(24\) 不是随便取的，而是「够用且能对齐」的最小值。

结论：**(1) 见解析的 C 代码；(2) 局部变量区 \(24\) 字节，数组 \(16\) 字节、填充 \(8\) 字节；(3) `f(7) = 17`；(4) `%rbx` 会被 `g` 覆盖，且违反被调用者保存约定；(5) 为了在 `call g` 前保持 \(16\) 字节对齐。**

## 常见错误

一是把 `buf` 还原成 3 个元素，或把 `-24(%rbp)` 当成填充——它其实是 `buf[1]`。二是认为 `subq $16` 就够了，忽略对齐，导致 `call g` 前 `%rsp` 余 \(8\)。三是忘记 `%rbx` 是被调用者保存寄存器，以为只有 `%rax` 会被 `call` 破坏。四是把 `addq -24(%rbp), %rax` 当成「把 `%rax` 存到 `-24`」，源和目的看反。五是以为 `-O0` 下编译器不会做这种「先用栈再用寄存器」的保存，实际上 `-O0` 的代码正是这样逐句翻译的。
