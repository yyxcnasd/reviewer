下面的 C 函数调用了 `g`：

```c
long h(long x) {
    long t = 3 * x;
    long u = g(x);
    return t + u;
}
```

编译后的汇编是

```
h:
    pushq %rbx
    leaq  (%rdi,%rdi,2), %rbx
    call  g
    addq  %rbx, %rax
    popq  %rbx
    ret
```

回答：

（1）为什么把 `t` 放在 `%rbx`，而不是 `%rax`、`%rdi` 或 `%r10`？

（2）`pushq %rbx` 与 `popq %rbx` 的作用是什么？如果删掉 `popq %rbx`，会破坏什么？

（3）调用 `g` 时 `%rdi` 里还是 `x`，而 `g` 可能改写 `%rdi`，为什么 `h` 不在 `call` 前保存它？

（4）用自己的话总结 caller-saved 与 callee-saved 两类寄存器的责任划分。

## 提示

关键看一个值是否要「跨过 `call` 存活」：`t` 在 `g` 返回后还要用，所以不能放在 `g` 可以随意改写的寄存器里。`caller-saved` 是调用者负责保存，`callee-saved` 是被调用者负责保存。

## 解析

（1）`%rax`、`%rdi`、`%r10` 都是 caller-saved（调用者保存）寄存器。`g` 作为被调用者可以任意改写它们，返回后 `t` 就丢了。`%rbx` 是 callee-saved 寄存器，`g` 必须保证返回时它和调用前一样，所以把 `t` 放在 `%rbx` 里能跨过 `call` 存活。

（2）`pushq %rbx` 把调用者的 `%rbx` 原值保存到栈上，`popq %rbx` 在返回前恢复它。删掉 `popq %rbx` 后，`h` 返回时 `%rbx` 里是 `t = 3x` 而不是调用者原来的值，破坏了调用者的寄存器状态，调用者后续用到 `%rbx` 就会算错。

（3）`%rdi` 是 caller-saved 的传参寄存器。`h` 在 `call g` 之后不再需要 `x`，所以 `g` 改写 `%rdi` 对 `h` 没有影响，不必保存。如果 `h` 在调用后还要用 `x`，就必须先把 `x` 存到 callee-saved 寄存器或栈上。

（4）caller-saved：调用者若希望某个值跨过 `call` 仍然有效，就自己负责保存（通常在调用前存到栈或 callee-saved 寄存器）；被调用者可以随意使用这些寄存器。callee-saved：被调用者若使用了这些寄存器，必须在返回前恢复原值；调用者可以放心地让值留在其中跨过调用。

## 常见错误

一是把 `%rbx` 当成 caller-saved，认为 `g` 可以随便改它，从而看不懂为什么要 `push`/`pop`。二是以为 `pushq %rbx` 是为了给 `g` 传参——传参用的是 `%rdi` 等，`push` 只是保存。三是认为 `%rdi` 在调用前后必须保持不变，其实 `%rdi` 是 caller-saved，被调用者可以改写。四是以为删掉 `popq %rbx` 只影响性能，实际上它破坏了调用者的寄存器状态，属于违反调用约定。
