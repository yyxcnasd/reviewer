在 32 位机器上，`int` 与 `unsigned` 都占 4 字节，整数用补码表示。回答：

(1) `int x = 0x80000000;` 中 `x` 的十进制值是多少？若忽略 C 的未定义行为、只按 32 位位模式回绕，`-x` 的位模式是什么？

(2) `unsigned u = (unsigned)-1;` 中 `u` 的值是多少？

(3) 表达式 `-1 < 0u` 的值是 \(0\) 还是 \(1\)？说明理由。

(4) `signed char c = (signed char)200;` 与 `unsigned char d = (unsigned char)-56;` 中 `c`、`d` 的值分别是多少？

## 提示

补码的最高位权重是负的，不是正的。有符号数与无符号数混合运算时，有符号数会先按模 \(2^{32}\) 转成无符号数再比较。窄类型赋值时先按模 \(2^{8}\) 截断，再按目标类型解释。

## 解析

**(1)** `0x80000000` 的二进制只有最高位是 \(1\)，作为 32 位补码，它的值是

\[
-2^{31}=-2147483648.
\]

`-x` 在数学上是 \(2^{31}=2147483648\)，但 `int` 最大只能到 \(2^{31}-1\)，这个运算在 C 里是未定义行为。如果只看位模式回绕，\(-(-2^{31})\) 仍得到 `0x80000000`，解释成 `int` 还是 \(-2147483648\)。

**(2)** `-1` 的 32 位位模式是全 \(1\)，转成无符号数就是

\[
2^{32}-1=4294967295.
\]

**(3)** `0u` 是无符号数，按 C 的寻常算术转换，`-1` 先转成无符号数 \(4294967295\)，再与 \(0\) 比较。于是实际比较的是

\[
4294967295<0,
\]

结果为假，整个表达式的值是 \(0\)。这是一个典型的陷阱：`-1 < 0u` 并不成立。

**(4)** `200` 的 8 位位模式是 `11001000`，按有符号补码解释：

\[
200-256=-56.
\]

所以 `c` 的值是 \(-56\)。而 `-56` 按模 \(256\) 回绕：

\[
-56+256=200,
\]

所以 `d` 的值是 \(200\)。两个赋值都只是「同一位模式换一种解释」，并没有改变位。

结论：**(1) `x = -2147483648`，`-x` 的位模式是 `0x80000000`；(2) `u = 4294967295`；(3) `-1 < 0u` 为假；(4) `c = -56`，`d = 200`。**

## 常见错误

一是认为 `-1 < 0u` 为真，忽略有符号数先转无符号这一步。二是把 `-x` 算成 \(2147483648\) 并当作 `int` 的合法值，忽略这是溢出。三是把 `signed char` 的 `200` 当成 \(200\)，忘了 8 位只有 \(-128\) 到 \(127\)。四是把「位模式」和「数值」混为一谈：`0x80000000` 这串位既可以读成 \(-2147483648\)，也可以读成 \(2147483648\)，取决于类型，而不是位本身变了。
