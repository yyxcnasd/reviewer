某函数对整数参数 `x`（放在 `%rdi`）做多分支分派，编译器生成的汇编片段是

```
    leal -10(%rdi), %eax
    cmpl $2, %eax
    ja .L8
    jmp *.L4(,%rax,8)
.L4:
    .quad .L5
    .quad .L6
    .quad .L5
```

(1) 这段代码支持的 `case` 值是哪些？每个值分别跳到哪个标签？其他值呢？

(2) 为什么不直接 `cmpl $12, %rdi` 再用 `%rdi` 查表？`leal -10(%rdi), %eax` 这一步的作用是什么？

(3) 当 `x` 分别取 9、10、12、13 时跳到哪个标签？如果 `x` 是负数呢？

(4) 如果 C 源码里 `x` 是 `long`，而有人照抄了这段 32 位的汇编，那么 `x = 2^{32}+10` 会发生什么？为什么？

(5) 跳转表每一项为什么用 `.quad`（8 字节）？`jmp *.L4(,%rax,8)` 里的比例因子 8 对应什么？

## 提示

先看 `leal -10(%rdi), %eax` 把 \(x\) 变成了什么：它算的是「\(x-10\) 的低 32 位」。`cmpl $2` 加 `ja`（无符号大于）同时完成两件事：上界检查和负数排除。查表时下标是平移后的值，不是原来的 \(x\)。

## 解析

**(1)** `leal -10(%rdi), %eax` 计算 \(E=x-10\)（取低 32 位）。`cmpl $2, %eax; ja .L8` 在无符号意义下判断 \(E>2\)，否则就是 \(E\in\{0,1,2\}\)，即 \(x\in\{10,11,12\}\)。

跳转表 `.L4` 三项依次对应 \(E=0,1,2\)：

- \(x=10\)（\(E=0\)）→ `.L5`；
- \(x=11\)（\(E=1\)）→ `.L6`；
- \(x=12\)（\(E=2\)）→ `.L5`。

其他任何 \(x\)（\(x<10\) 或 \(x>12\)）都跳到 `.L8`（default 分支）。

**(2)** 如果直接用 \(x\) 当表下标，`case` 值从 10 开始，跳转表就要有 13 项（下标 0–12），其中 0–9 是 10 个空洞。`leal -10` 把值域平移到从 0 开始，表只要 3 项。

同时，**无符号比较** `ja` 让一条指令完成两个判断：

- 若 \(x<10\)，则 \(E=x-10\) 是负数，作为无符号数是巨大的值，`ja` 成立 → default；
- 若 \(x>12\)，则 \(E>2\)，`ja` 也成立 → default。

如果改用有符号比较，负数不会「大于 2」，就会继续往下执行 `jmp`，用负下标访问跳转表——越界读到垃圾地址，这正是 CSAPP 里强调的「负下标」陷阱。

**(3)** 逐一代入：

- \(x=9\)：\(E=-1\)，无符号是 \(2^{32}-1>2\)，跳 `.L8`；
- \(x=10\)：\(E=0\)，跳 `.L5`；
- \(x=12\)：\(E=2\)，跳 `.L5`；
- \(x=13\)：\(E=3>2\)，跳 `.L8`。

负数同理：\(x=-1\) 时 \(E=-11\)，无符号极其巨大，`ja` 命中，跳 `.L8`。

**(4)** 会**错误地命中 `case 10`**。

`leal -10(%rdi), %eax` 是 32 位运算：它只取 `%rdi` 的低 32 位来计算。当 \(x=2^{32}+10\) 时，低 32 位就是 10，于是 \(E=0\)，`ja` 不成立，跳转表第 0 项 → `.L5`，和真正的 `x=10` 走了同一个分支。

但按 C 的 `switch (long x)` 语义，\(2^{32}+10\) 不等于 10，应当走 default。所以这段 32 位汇编只对 `int` 参数正确；编译器为 `long` 参数生成的是 `leaq -10(%rdi), %rax` + `cmpq $2, %rax` + `jmp *.L4(,%rax,8)`。

**(5)** 跳转表里存的是**代码地址**。x86-64 的地址是 64 位，所以每项必须 8 字节（`.quad`），查表时的比例因子也必须是 8：

\[
\text{目标地址}=\text{表基址}+8\times E.
\]

如果用 `.long`（4 字节）而比例因子仍写 8，就会每隔一项跳到一个错误的位置。

## 常见错误

一是把 \(E=x-10\) 当成 \(x\) 直接查表，导致整体错位（\(x=10\) 会去查第 10 项）。二是把 `ja` 解释成有符号比较，认为 \(x=9\) 会进入 `case`。三是忽略「32 位写操作会截断」，认为 \(x=2^{32}+10\) 也会被正确排除。四是把表项宽度当成 4 字节，或忘记 8 字节比例因子与 64 位地址的对应关系。五是认为 default 分支一定由 `jmp` 表覆盖，其实边界检查才是 default 的入口。
