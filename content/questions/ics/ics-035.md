下面的 C 函数返回两个 `long` 参数之差的绝对值：

```c
long maxdiff(long x, long y) {
    if (x > y)
        return x - y;
    return y - x;
}
```

参数 `x`、`y` 分别放在 `%rdi`、`%rsi`，返回值放在 `%rax`。

（1）写出带条件跳转的 x86-64 汇编实现（AT&T 语法），并标注每条指令的作用。

（2）用 `cmov` 写出无分支版本，说明它相对分支版的好处。

（3）如果参数类型改成 `unsigned long`，条件跳转应该换成哪条指令？为什么？

（4）如果参数类型改成 `int`，这个实现在什么输入下会出错？举一个具体例子。

## 提示

AT&T 语法里 `cmpq %rsi, %rdi` 计算的是 `%rdi - %rsi`，条件跳转据此判断 `x` 与 `y` 的大小。`cmovcc` 根据条件码决定是否把源操作数搬到目的寄存器，可以在不跳转的情况下二选一。

## 解析

（1）带条件跳转的版本：

```
maxdiff:
    cmpq  %rsi, %rdi      # 计算 x - y，设置条件码
    jle   .L2             # 若 x <= y 跳到 .L2
    movq  %rdi, %rax      # rax = x
    subq  %rsi, %rax      # rax = x - y
    ret
.L2:
    movq  %rsi, %rax      # rax = y
    subq  %rdi, %rax      # rax = y - x
    ret
```

`jle` 的含义是「小于或等于」（有符号），即 `x <= y` 时走 `.L2` 分支；否则顺序执行，返回 `x - y`。

（2）无分支版本：先把两个差都算出来，再用 `cmovle` 选。

```
maxdiff:
    movq  %rdi, %rax
    subq  %rsi, %rax      # rax = x - y
    movq  %rsi, %rdx
    subq  %rdi, %rdx      # rdx = y - x
    cmpq  %rsi, %rdi      # 比较 x 与 y
    cmovle %rdx, %rax     # 若 x <= y，则 rax = rdx = y - x
    ret
```

好处是消除了不可预测的分支。当 `x`、`y` 的分布随机时，条件跳转的预测失败率很高，流水线要清空重来；`cmov` 把选择变成一条数据相关的指令，代价固定。缺点是两条减法都要算，且 `cmov` 仍依赖条件码，不能完全消除数据相关。

（3）改成 `unsigned long` 后，比较应使用无符号条件码：
- 条件跳转版：`jbe .L2`（无符号小于或等于）；
- 无分支版：`cmovbe %rdx, %rax`。
因为 `unsigned` 的「大」是按 \(0\) 到 \(2^{64}-1\) 的顺序判断的，带符号的 `jle`/`cmovle` 会把最高位为 1 的大无符号数误判为「小」（负数）。

（4）改成 `int` 后，减法可能溢出。例如
```c
maxdiff(INT_MIN, 1)
```
要走 `x <= y` 分支，计算 `y - x = 1 - (-2147483648) = 2147483649`，超出 `int` 的范围，C 语言中有符号溢出是未定义行为，机器上得到 `-2147483647` 之类的错误结果。`long` 版本因为 64 位范围大得多，只要 `x`、`y` 本身是 `long` 就不会出现这个问题。

## 常见错误

一是把 AT&T 的 `cmpq %rsi, %rdi` 的方向记反，写成 `cmpq %rdi, %rsi`，导致 `jle` 判断的其实是 `y <= x`。二是 `jle` 与 `jge` 用混：这里「不大于」对应 `jle`。三是无符号版本只改数据类型、忘改条件码，仍用 `jle`/`cmovle`。四是以为 `cmov` 版本一定更快——它在两个差都要算、分支高度可预测时反而多做了工作。五是忽略 `int` 版 `INT_MIN - 1` 这种溢出。
