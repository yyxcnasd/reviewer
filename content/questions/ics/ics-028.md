下面这段代码把网络包复制到栈上的缓冲区：

```c
void copy_packet(const char *src, int len) {
    char buf[64];
    if (len <= 64)
        memcpy(buf, src, len);
}
```

回答：

(1) 当 `len = -1` 时，`if` 检查能通过吗？`memcpy` 实际会复制多少字节？会发生什么？

(2) `memcpy` 的第三个参数是什么类型？`len` 传进去时发生了什么转换？

(3) 至少给出两种修复方法。

(4) 如果把条件改成 `len < 64`，能防住 `len = -1` 吗？为什么？

(5) 这个漏洞与缓冲区溢出是什么关系？为什么说「边界检查写对了也可能被绕过」？

## 提示

`len` 是 `int`，而 `memcpy` 的第三个参数是 `size_t`（无符号）。比较 `len <= 64` 时用的是有符号比较，`-1` 当然小于 \(64\)；但传参时 `-1` 会按模 \(2^{64}\) 变成巨大的无符号数。检查用的类型和拷贝用的类型不一致，是这类漏洞的根源。

## 解析

**(1)** `len` 是 `int`，`-1 <= 64` 为真，检查通过。进入 `memcpy` 时，第三个参数按 `size_t` 解释：

\[
(\texttt{size\_t})(-1)=2^{64}-1=18446744073709551615.
\]

`memcpy` 会尝试从这个源地址复制近乎无限多的字节，远超出 `buf` 的 \(64\) 字节，造成严重的栈溢出，通常会直接段错误；在特定条件下也可能被利用来劫持控制流。

**(2)** `memcpy` 的原型是

```c
void *memcpy(void *dest, const void *src, size_t n);
```

第三个参数类型是 `size_t`，在 64 位平台上就是 `unsigned long`。C 在传参时把 `int` 转成 `size_t`：非负值不变，负值按模 \(2^{64}\) 回绕，所以 \(-1\) 变成 \(2^{64}-1\)。

**(3)** 修复的关键是让「检查」和「使用」用同一种类型，并同时限制上下界：

```c
void copy_packet(const char *src, size_t len) {
    char buf[64];
    if (len <= sizeof(buf))
        memcpy(buf, src, len);
}
```

或者保留 `int`，但把负值也排除：

```c
void copy_packet(const char *src, int len) {
    char buf[64];
    if (len >= 0 && len <= (int)sizeof(buf))
        memcpy(buf, src, len);
}
```

也可以改用有界接口（如 `snprintf`、带长度参数的 `read`/`fgets`），从源头限制拷贝量。

**(4)** 不能。`-1 < 64` 仍然为真，负值照样通过检查。把 `<=` 改成 `<` 只改变了上界的一个边界，完全没有处理负数。

**(5)** 这是缓冲区溢出的一个典型入口：边界检查本身写出来了，但检查用的是有符号 `int`，拷贝用的是无符号 `size_t`，攻击者用一个负长度就能让检查失效，随后 `memcpy` 按巨大的长度写入，踩坏栈上的返回地址等数据。

它说明「检查写对了」不够，还要保证：检查的变量类型与真正参与运算/传参的类型一致；上下界都检查（这里上界是 `sizeof(buf)`，下界是 \(0\)）；长度在检查之后不会再被改变。只防住一个方向，另一个方向就可能成为绕过点。

结论：**(1) 检查通过，`memcpy` 会复制 \(2^{64}-1\) 字节，造成栈溢出或崩溃；(2) 第三个参数是 `size_t`，负数按模 \(2^{64}\) 转换；(3) 改用 `size_t` 并检查上界，或同时检查 `len >= 0`；(4) 不能，`-1 < 64` 仍为真；(5) 有符号与无符号不一致导致边界检查被绕过，属于缓冲区溢出。**

## 常见错误

一是认为 `len <= 64` 会拒绝 \(-1\)：有符号比较下 \(-1\) 确实小于 \(64\)。二是以为 `memcpy` 会自动截断到 `buf` 的大小，它根本不知道 `buf` 有多大。三是用 `len < 64` 或 `len <= 64` 就以为修好了，没处理负数。四是只把 `buf` 改大，不改变检查逻辑，攻击者仍可用巨大长度越过。五是忽略 `memcpy` 参数的类型转换，把「值」和「位模式」混为一谈：\(-1\) 的位模式转成无符号就是 \(2^{64}-1\)。
