递归函数 `rec` 在 `-O0` 下的汇编如下（参数 `n` 是 `int`，在 `%edi`；返回值是 `long`，在 `%rax`）：

```
rec:
    pushq %rbp
    movq  %rsp, %rbp
    subq  $16, %rsp
    movl  %edi, -4(%rbp)
    testl %edi, %edi
    jne   .L2
    movl  $0, %eax
    jmp   .L3
.L2:
    movl  -4(%rbp), %eax
    subl  $1, %eax
    movl  %eax, %edi
    call  rec
    addl  -4(%rbp), %eax
.L3:
    leave
    ret
```

回答：

(1) 还原 `rec` 的 C 代码（注意返回类型是 `long`，而 `n` 是 `int`，说明返回值是怎么扩宽的）；

(2) 每一次调用 `rec` 在栈上消耗多少字节？默认栈限制为 \(8\ \text{MiB}\) 时，最多能递归多少层？

(3) 这个函数能被编译器优化成循环（尾递归消除）吗？为什么？

(4) 改写成一个**尾递归**版本，并说明 `-O2` 下它会被编译成什么形态；

(5) 若传入 \(n=10^7\)，实际会发生什么？给出两种避免方法。

## 提示

每层调用的栈消耗 = `call` 压的返回地址 + `pushq %rbp` 的 8 字节 + `subq` 减掉的字节。注意递归到最深处时，所有层的这些开销是**同时**占着的。

能不能尾递归消除，只看一件事：递归调用返回之后，函数是否还需要做事（本题是 `addl`）。

## 解析

**(1)** 逐句翻译：

- `movl %edi, -4(%rbp)`：把参数 \(n\) 存到局部变量；
- `testl %edi, %edi` + `jne .L2`：\(n\ne0\) 跳到 `.L2`，否则返回 \(0\)；
- `.L2` 里把 \(n-1\) 放进 `%edi`，`call rec`，返回后在 `%rax` 里拿到 `rec(n-1)`；
- `addl -4(%rbp), %eax`：把 \(n\) 加到返回值上。

所以

```c
long rec(int n) {
    if (n == 0) return 0;
    return n + rec(n - 1);
}
```

返回类型 `long` 而 \(n\) 是 `int`：`n + rec(n-1)` 里 `n` 会被隐式转换成 `long` 再相加，结果累加在 64 位寄存器里。

**(2)** 每次调用占用：

\[
\underbrace{8}_{\text{返回地址}}+\underbrace{8}_{\text{保存的 }\%rbp}+\underbrace{16}_{\texttt{subq}\ \$16}=32\ \text{字节}.
\]

注意 `subq $16` 里只有 4 字节是 `n`，其余是对齐/填充（`-O0` 下编译器按 16 字节为单位分配局部区）。

\(8\ \text{MiB}\) 栈：

\[
\frac{8\times1024\times1024}{32}=262144,
\]

所以大约 \(2^{18}\) 层后就会耗尽栈空间。实际可用层数还要减去 `main` 和启动代码已占的部分，比这个数略小。

**(3)** 不能。尾递归消除的条件是：递归调用是函数返回前的**最后**一个动作（返回值就是递归调用的返回值）。本题 `call rec` 之后还有 `addl -4(%rbp), %eax`，递归结果还要再加工，所以每层都必须保留自己的栈帧和局部变量，无法压平成循环。

**(4)** 把"待加工的加法"改成参数传下去，递归调用成为最后一步：

```c
long rec_tail(int n, long acc) {
    if (n == 0) return acc;
    return rec_tail(n - 1, acc + n);
}
```

调用时用 `rec_tail(n, 0)`。`-O2` 下编译器会把它变成等价的循环：

```c
long rec_tail(int n, long acc) {
    while (n != 0) { acc += n; n -= 1; }
    return acc;
}
```

此时栈深度是常数，与 \(n\) 无关；递归写法不再消耗 \(O(n)\) 栈空间。

**(5)** \(n=10^7\) 远超 \(262144\) 层，递归到约 \(2.6\times10^5\) 层时 `%rsp` 撞到栈的边界，触发栈溢出，进程收到 SIGSEGV（表现为段错误，不是打印"栈溢出"）。

两种避免方法：

1. 改成迭代（或尾递归并开启 `-O2`），栈深度变成 \(O(1)\)；
2. 增大栈限制，例如 Linux 下 `ulimit -s 65536`（64 MiB），但这只是把问题推后，`n` 更大时仍会崩。

## 常见错误

- 把每次调用的开销算成 \(16\) 字节（只算 `subq`），漏掉返回地址和保存的 `%rbp`。
- 认为 `subq $16` 里"4 字节存 n、12 字节浪费"，却没意识到栈帧是按对齐分配的；算总占用时必须用 `subq` 的实际值。
- 认为递归函数都能被尾递归消除。含"调用后还要加工"的递归不能直接消除，必须先改写成累加器形式。
- 把栈溢出与堆溢出、缓冲区溢出混为一谈。这里没有越界写，只是 `%rsp` 触碰了栈的下界；崩溃是"访问未映射页"。
- 用 `8 MiB / 32` 得 262144 后直接说"能递归 262144 次"；实际因 `main` 已占若干帧而略少，答"约"更稳妥。
