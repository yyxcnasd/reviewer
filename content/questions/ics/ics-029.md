一个 C 程序从源文件变成可执行文件，要经过预处理、编译、汇编、链接几个阶段。指出下列现象分别发生在哪个阶段，并简述理由。

（1）gcc 报错 `fatal error: stdio.h: No such file or directory`。

（2）gcc 报错 `error: 'x' undeclared (first use in this function)`。

（3）gcc 报错 `undefined reference to 'foo'`。

（4）汇编器报错 `Error: no such instruction: 'movq %rax,%rbx,'`（末尾多了一个逗号）。

（5）编译、链接都成功，运行时出现 `Segmentation fault`。

（6）同一个函数在 `a.c` 和 `b.c` 里各定义了一次，gcc 报 `multiple definition of 'foo'`。

## 提示

判断依据是「这个阶段手上有哪些文件、能看到什么信息」：预处理只看源文件和头文件，编译看 C 语法与声明，汇编只看汇编指令，链接看目标文件的符号表，运行才真正访问内存。

## 解析

**关键的那一步为什么能想到。** 不要凭「报错看起来像什么」猜，而是问：此时编译器手里是 `.c`、`.s`、`.o` 还是可执行文件？哪个阶段掌握了发现这个错误所需的信息，错误就属于哪个阶段。用这条线索，六个现象可以一一归位。

（1）**预处理**。`#include` 是预处理指令，预处理器要找到并读入 `stdio.h` 的全文。文件找不到时预处理就失败，此时还没有进入语法分析。

（2）**编译**。编译器做语法与语义分析，发现标识符 `x` 没有声明。源文件里没有 `x` 的定义或声明，编译器无法生成访问它的代码，只能在这里报错。

（3）**链接**。`foo` 在源文件里有声明（或隐式声明），编译器能生成一条「调用外部符号 `foo`」的重定位记录，并把活交给链接器。链接器在所有目标文件和库中找不到 `foo` 的定义，于是报 `undefined reference`。

（4）**汇编**。gcc 已经把 C 翻译成汇编、交给汇编器 `as`。`movq %rax,%rbx,` 里的指令助记符和操作数格式是汇编器负责编码的，多出的逗号让汇编器无法解析，所以停在汇编阶段。

（5）**运行**。可执行文件已经生成。段错误是程序运行时访问了非法地址（空指针、越界、栈溢出等）由操作系统发出的信号，与编译链接无关。

（6）**链接**。两个目标文件都导出了全局符号 `foo`，链接器做符号解析时发现同名强符号冲突，报 `multiple definition`。编译每个文件时都看不到对方，所以不可能在编译阶段发现。

补充一句区分：`undeclared` 是「编译期没有声明」，`undefined reference` 是「链接期没有定义」。前者说明名字在源文件里根本没出现，后者说明名字出现了、代码生成了，只是定义在别处找不到。

## 常见错误

一是把 `undefined reference` 当成编译错误——它恰恰说明编译已经通过、只差链接。二是把 `multiple definition` 当成编译错误，其实每个 `.c` 单独编译都没问题，是链接时符号表冲突。三是以为头文件找不到是链接问题：头文件的搜索与包含完全在预处理阶段完成。四是把运行时段错误归咎于编译器，忽略程序已经生成这一事实。
