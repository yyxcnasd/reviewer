函数 `sum` 的汇编实现如下（参数 `a` 在 `%rdi`，`n` 在 `%rsi`，返回值在 `%rax`）：

```
sum:
    movl  $0, %eax
    movl  $0, %ecx
    jmp   .L2
.L3:
    movq  (%rdi,%rax,8), %rdx
    addq  %rdx, %rcx
    addq  $1, %rax
.L2:
    cmpq  %rsi, %rax
    jl    .L3
    movq  %rcx, %rax
    ret
```

（1）写出与之等价的 C 代码（用 `while` 或 `for`）。

（2）若 `a = {1, -2, 3, -4}`、`n = 4`，函数返回多少？

（3）如果把 `jl` 改成 `jle`，循环会怎样变化？会带来什么问题？

（4）如果数组元素类型从 `long` 改成 `int`，需要修改哪些指令？如果改成 `unsigned int` 呢？

## 提示

先找循环的三要素：循环变量、循环条件、循环体。`%rax` 从 0 开始每轮加 1，`%rcx` 累加 `a[i]`，`jl` 是「有符号小于」。注意 AT&T 的 `cmpq %rsi, %rax` 计算的是 `%rax - %rsi`。

## 解析

**关键的那一步为什么能想到。** 汇编里的循环通常由「初始化 → 跳到条件判断 → 循环体 → 条件判断」四块组成。先找出哪个寄存器在递增（`%rax`，即 `i`）、哪个在累加（`%rcx`，即 `s`）、哪个数在控制终止（`%rsi`，即 `n`），再按 `cmp` 的操作数方向读出条件是 `i < n`。把这三件事对上，C 代码就出来了。

（1）等价 C 代码：

```c
long sum(long *a, long n) {
    long i = 0;
    long s = 0;
    while (i < n) {
        s += a[i];
        i++;
    }
    return s;
}
```

（2）逐项累加：
\[
1+(-2)+3+(-4)=-2.
\]
所以返回 `-2`。

（3）`jl` 是有符号「小于」，改成 `jle` 后条件变成 \(i\le n\)，循环体会执行 \(n+1\) 次，最后一次用 \(i=n\) 访问 `a[n]`。`a` 的有效下标是 \(0\) 到 \(n-1\)，`a[n]` 已经越界，属于未定义行为：可能读到相邻变量、触发放错误的内存保护，也可能只是悄悄返回一个错值。

（4）`long` 元素占 8 字节，所以用 `movq` 和比例因子 8。改成 `int`（4 字节）后：
- 取数指令要变成 `movslq (%rdi,%rax,4), %rdx`——`movslq` 把 32 位有符号数符号扩展到 64 位，才能参与 `addq` 的 64 位加法；
- 比例因子由 8 改成 4；
- 其余（`addq`、`cmpq`、返回 `long`）不变。

如果元素是 `unsigned int`，则用 `movl (%rdi,%rax,4), %edx` 即可：32 位写 `%edx` 时高 32 位自动清零，等价于零扩展，不需要 `movslq`。

## 常见错误

一是把 `cmpq %rsi, %rax` 的方向读反，写成条件 `n < i`，导致判断循环一次都不执行。二是把 `%rcx` 当成循环变量、`%rax` 当成累加器，寄存器角色看错。三是没注意 `jl` 是有符号比较：如果 `n` 是负数，`i < n` 一开始就不成立，循环不执行；若换成 `jb`（无符号），负数会被当成巨大的无符号数，循环会越界跑很久。四是改 `int` 数组时只改比例因子、忘了用 `movslq` 做符号扩展，或者对 `unsigned` 误用 `movslq`。
