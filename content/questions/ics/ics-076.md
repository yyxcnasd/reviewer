两个函数分别处理二维数组。`%rdi` 是数组首地址，`%rsi` 是行下标，`%rdx` 是列下标：

```
f:
    leaq    (%rsi,%rsi,4), %rax     # rax = 5*i
    leaq    (%rdx,%rax,2), %rax     # rax = j + 2*(5i) = 10i + j
    movq    (%rdi,%rax,8), %rax     # 取 8*(10i+j) 处的 8 字节
    ret

g:
    leaq    (%rsi,%rsi,4), %rax     # rax = 5*i
    leaq    (%rax,%rax,3), %rax     # rax = 4*(5i) = 20i
    leaq    (%rdx,%rax), %rax       # rax = 20i + j
    movl    (%rdi,%rax,4), %eax     # 取 4*(20i+j) 处的 4 字节
    ret
```

(1) 反推 `f` 的 C 函数声明（元素类型、列数）与返回值，并说明每一步 `leaq` 在做什么。

(2) 反推 `g` 的 C 函数声明，并说明它的元素大小与列数是怎么从汇编里读出来的。

(3) 若 `f` 的参数声明为 `long a[][10]`，在 `f` 内部 `sizeof(a)` 是多少？`a + 1` 与 `a` 相差多少字节？`&a[2][3]` 相对 `a` 偏移多少？

(4) 调用 `f(a, 1, 10)` 时实际访问的是哪个元素？为什么不会触发越界错误？

(5) 为什么 `leaq (%rsi,%rsi,4)` 再 `leaq (%rdx,%rax,2)` 就能唯一确定是 \(10i+j\)，而不是别的分解？推理依据是什么？

## 提示

`leaq (%a,%b,S)` 计算 \(a+S\cdot b\)，`S` 只能是 1、2、4、8，正好对应元素大小。二维数组行优先：`a[i][j]` 的地址是首地址加 \((i\cdot C+j)\times\text{sizeof}(T)\)，所以汇编里"先乘 \(C\)、再加 \(j\)、最后乘元素大小"的三段结构就是列数和元素类型的指纹。

## 解析

**(1)** 逐条还原：

\[
\begin{aligned}
\text{rax} &= 5i &&(\texttt{leaq (\%rsi,\%rsi,4)})\\
\text{rax} &= j+2\cdot(5i)=10i+j &&(\texttt{leaq (\%rdx,\%rax,2)})\\
\text{地址} &= a+8\cdot(10i+j) &&(\texttt{movq (\%rdi,\%rax,8)})
\end{aligned}
\]

所以元素是 8 字节（`movq` + scale 8），每行 10 个（系数 10），`f` 返回第 \(10i+j\) 个元素：

```c
long f(long (*a)[10], long i, long j) {
    return a[i][j];
}
```

**为什么想到**：`5i` 再用 scale 2 变成 `10i`，是因为 `leaq` 的 scale 最大只有 8，编译器常用「先乘 5、再乘 2」拼出 10；而 `+j` 与 `*8` 分别对应「列下标」与「元素大小」。

**(2)** 同理：

\[
\begin{aligned}
\text{rax} &= 5i &&(\texttt{leaq (\%rsi,\%rsi,4)})\\
\text{rax} &= 4\cdot(5i)=20i &&(\texttt{leaq (\%rax,\%rax,3)})\\
\text{rax} &= 20i+j &&(\texttt{leaq (\%rdx,\%rax)})\\
\text{地址} &= a+4\cdot(20i+j) &&(\texttt{movl (\%rdi,\%rax,4)})
\end{aligned}
\]

`movl` 取 4 字节，所以元素是 `int`；系数 20 是列数：

```c
int g(int (*a)[20], long i, long j) {
    return a[i][j];
}
```

**为什么想到**：判断元素大小看最后一条访存指令的后缀与 scale（`movl` + 4 → 4 字节）；判断列数看"乘到行下标上的系数"（20）。

**(3)** 函数参数里的 `a` 已经退化成**指针**（指向含 10 个 `long` 的数组），不再有数组类型的大小信息：

\[
\begin{aligned}
\texttt{sizeof}(a) &= 8 &&(\text{一个指针}),\\
a+1 &= a + 10\times8 = a+80\ \text{字节},\\
\&a[2][3] &= a + (2\times10+3)\times8 = a+184\ \text{字节}.
\end{aligned}
\]

注意 `sizeof` 算的是指针，不是 \(10\times8=80\)；想知道行长度只能靠类型里的 `[10]`，而不能靠 `sizeof(a)`。

**(4)** \(f(a,1,10)\) 算出的偏移是

\[
(1\times10+10)\times8=160\ \text{字节},
\]

而 `a[2][0]` 的偏移是 \((2\times10+0)\times8=160\) 字节——两者**地址相同**。也就是说 `a[1][10]` 实际读的是下一行的第一个元素。

C 不会做数组边界检查：编译器只按公式算地址然后读内存，所以既不报错也不崩溃（除非恰好越过整个数组的末尾掉进未映射页）。但语义上 `j=10` 已经越界，属于未定义行为，结果不可依赖。

**为什么想到**：行优先的地址是线性的，`a[i][C]` 必然等于 `a[i+1][0]`；"不报错"不等于"合法"，只是没有检查。

**(5)** 推理链是：

\[
\begin{aligned}
&\text{scale }8\ \Rightarrow\ \text{元素 8 字节};\\
&\text{内层 }\text{rax}=j+2\cdot(5i)\ \Rightarrow\ \text{行系数 }=10;\\
&\text{行优先公式 } a+(iC+j)\cdot8\ \Rightarrow\ C=10.
\end{aligned}
\]

`leaq` 的三种写法（scale 1/2/4/8、加法）能表达的线性组合有限：要得到 \(i\) 的系数 \(10\)，最自然的就是 \(2\times5\) 或 \(5\times2\)；元素大小又被最后的 scale 固定为 8。若换一个列数（比如 12），`i` 的系数就变了，这两条 `leaq` 的常数必须跟着变——所以"系数 + scale"这对指纹足以唯一确定 \((C,\text{sizeof})\)。

**注意**：单看一条 `leaq (%rsi,%rsi,4)`（\(5i\)）并不能断言什么，必须结合后面如何继续组合、以及访存指令的 scale，才能锁死列数。这也是反推题的标准流程：先看访存（元素大小），再看系数（列数），最后验证下标顺序。

## 常见错误

一是把 `leaq (%rax,%rax,2)` 看成 \(3i\) 而不是 \(2\times\)（scale 2 是"乘以 2"，加上自身）。二是把 `sizeof(a)` 当成 \(10\times8=80\)，忘记函数参数中的数组已退化为指针。三是把 `a[1][10]` 判成"越界所以程序一定崩"，实际上它和 `a[2][0]` 同地址、可能静默读到错误数据。四是只用一条 `leaq` 就下结论，没有结合访存后缀确认元素大小。
