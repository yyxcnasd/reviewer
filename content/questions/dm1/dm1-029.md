设公式

\[
A=(\neg p\to q)\vee\bigl(r\wedge\neg(s\vee t)\bigr).
\]

(1) 写出 \(A\) 的波兰表达式和逆波兰表达式；

(2) 取 \(p=1,\ q=0,\ r=1,\ s=0,\ t=0\)，用逆波兰式从左到右、借助栈求 \(A\) 的值，写出每一步栈里的内容；

(3) 说明为什么波兰式与逆波兰式可以完全不要括号，而中缀式不行；并指出上一问的求值过程用到了"运算符元数"这一事实的哪一面。

## 提示

(1) 画出语法树：主联结词是 \(\vee\)，左边是 \(\neg p\to q\)，右边是 \(r\wedge\neg(s\vee t)\)。前缀式把每个子式的联结词提到该子式最前，后缀式放到最后。

(2) 逆波兰式从左向右扫：遇到操作数压栈，遇到运算符就弹出相应个数的操作数，算出结果再压回去。

## 解析

(1) 先写清树结构：

\[
A=\vee\bigl(\to(\neg p,q),\ \wedge(r,\ \neg(\vee(s,t)))\bigr).
\]

波兰表达式（前缀）：

\[
\vee\to\neg p q\wedge r\neg\vee s t.
\]

逆波兰表达式（后缀）：

\[
p\neg q\to r s t\vee\neg\wedge\vee.
\]

(2) 用栈模拟逆波兰式 \(p\neg q\to r s t\vee\neg\wedge\vee\)：

| 读到 | 操作 | 栈（底 \(\to\) 顶） |
|---|---|---|
| \(p\) | 压 \(1\) | 1 |
| \(\neg\) | 弹出 1，算 \(\neg1=0\)，压回 | 0 |
| \(q\) | 压 \(0\) | 0, 0 |
| \(\to\) | 弹 \(0,0\)，算 \(0\to0=1\)，压回 | 1 |
| \(r\) | 压 \(1\) | 1, 1 |
| \(s\) | 压 \(0\) | 1, 1, 0 |
| \(t\) | 压 \(0\) | 1, 1, 0, 0 |
| \(\vee\) | 弹 \(0,0\)，算 \(0\vee0=0\) | 1, 1, 0 |
| \(\neg\) | 弹 \(0\)，算 \(\neg0=1\) | 1, 1, 1 |
| \(\wedge\) | 弹 \(1,1\)，算 \(1\wedge1=1\) | 1, 1 |
| \(\vee\) | 弹 \(1,1\)，算 \(1\vee1=1\) | 1 |

最后栈里只剩一个元素 \(1\)，所以 \(A=1\)。

(3) 前缀式（逆波兰式）中，每个运算符的元数是固定的：\(\neg\) 一元，其余二元。扫描时每读到一个运算符，就知道该往前（往后）取几个操作数，整个符号串的解析方式唯一，等价于唯一一棵语法树，所以不需要括号来消歧。

中缀式不同：\(p\to q\vee r\) 既可以读成 \((p\to q)\vee r\)，也可以读成 \(p\to(q\vee r)\)。要靠三条约定之一来消歧：括号、优先级（\(\neg>\wedge>\vee>\to>\leftrightarrow\)）、结合性。约定一变，同一个符号串的意思就变，所以中缀式离不开括号或优先级规则。

第 (2) 问恰好用了"元数已知"这一点：读到 \(\to\) 时立刻知道要弹两个操作数，不需要回头找它的左边界——这正是无括号表示在机器处理上的优势。

## 常见错误

- 把 \(\neg p\to q\) 的前缀写成 \(\to p\neg q\)，\(\neg\) 和操作数的位置颠倒。正确的片段是 \(\to\neg p q\)。
- 转换逆波兰式时把 \(\neg(s\vee t)\) 写成 \(s t\vee\neg\) 之外的形式，例如 \(s t\neg\vee\)，那是 \((\neg s)\vee t\)。
- 求值时 \(\to\) 的两个操作数顺序搞反：\(0\to0=1\)，但若把顺序当成 \(1\to0\) 就会算成 0。
- 认为"波兰式不需要括号"是因为"波兰式更简单"。真正的原因是运算符元数固定带来的唯一可解析性。
