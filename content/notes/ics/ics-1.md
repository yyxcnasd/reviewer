## 1.1 计算机系统的层次与抽象

### 一台计算机就是一层层虚拟机

冯·诺依曼结构的要点是「存储程序」：指令和数据放在同一个存储器里，CPU 反复执行「取指—译码—执行」的循环，由程序计数器（PC）指出下一条指令的地址。现代计算机还多了存储层次和并行机制，但这条主线没变。

从下往上大致是：数字电路 → 微体系结构 → 指令集体系结构（ISA）→ 操作系统 → 汇编语言 → 高级语言 → 应用程序。每一层只把接口暴露给上层，把实现藏起来，这就是抽象。

ISA 是软硬件的分界。同一套 ISA（例如 x86-64）可以有不同微体系结构的实现；不同 ISA（x86-64 与 ARM）的机器码互不通用，但同一份 C 源码可以分别编译成两套指令。做题时判断「这段代码能不能在另一台机器上直接跑」，看的就是 ISA 是否相同。

### 抽象是好事，也是坑

抽象让写程序不必关心门电路，但分析性能、调试底层错误时必须「下钻」一层：

- C 里一句 `a[i]`，在汇编层是「地址计算 + 一条 load」。如果数据不在缓存里，这一条 load 要等上百个周期。
- C 里 `int` 的溢出、移位、类型转换，在语言层只说「未定义 / 实现相关」，到机器层都是明确的位运算和条件码。

所以复习这门课的姿势是：每学一个抽象，都问一句「它在机器层对应什么」。

### 存储层次与局部性

存储层次从快到慢：寄存器 → L1 缓存 → L2 → L3 → 主存 → 磁盘。越往下容量越大、越慢、每字节越便宜。

能这样设计，靠的是程序的**局部性**：

- 时间局部性：刚访问过的数据很可能马上再被访问（循环变量、反复调用的函数）；
- 空间局部性：一个地址被访问后，它附近的地址很可能紧接着被访问（顺序遍历数组）。

### 性能：三个因素一个都不能少

衡量程序性能的主公式是

\[
T=\frac{\text{指令数}\times \text{CPI}}{\text{主频}},
\]

其中 CPI 是每条指令平均消耗的时钟周期数，主频的单位是「周期/秒」（\(2.5\,\text{GHz}=2.5\times10^{9}\) 周期/秒）。加速比定义为旧时间除以新时间。

**最容易算错的一步**：以为「指令数变少就一定变快」。指令数和 CPI 往往此消彼长，必须把两者一起算。

**例**：主频 \(2.5\,\text{GHz}\)，程序执行 \(5.0\times10^{9}\) 条指令，平均 CPI 为 \(1.6\)，则

\[
T=\frac{5.0\times10^{9}\times1.6}{2.5\times10^{9}}=3.2\ \text{s}.
\]

若优化后指令数降为 \(4.0\times10^{9}\)，但 CPI 升到 \(2.0\)，则

\[
T'=\frac{4.0\times10^{9}\times2.0}{2.5\times10^{9}}=3.2\ \text{s},\qquad \text{加速比}=\frac{3.2}{3.2}=1.
\]

一点没快。原因：\(20\%\) 的指令数减少被 \(25\%\) 的 CPI 上升吃掉了。这说明性能优化必须看整体，单看一个指标会得出错误结论。

## 1.2 程序的一生：从 C 到可执行文件

### 四个阶段

一份 `hello.c` 变成可执行文件，要经过四步：

```
hello.c --预处理--> hello.i --编译--> hello.s --汇编--> hello.o --链接--> hello
```

1. **预处理**（`gcc -E`）：展开 `#include`、替换 `#define` 宏、处理条件编译，输出纯 C 文本 `.i`。
2. **编译**（`gcc -S`）：把 C 翻译成汇编，输出 `.s`。
3. **汇编**（`gcc -c`）：把汇编逐条翻成机器码，打包成可重定位目标文件 `.o`（ELF 格式，含机器码、符号表、重定位信息）。
4. **链接**（`gcc`，内部调用 `ld`）：把多个 `.o` 和库里的目标文件拼起来，做符号解析和重定位，输出可执行文件。

运行时，操作系统的加载器把可执行文件的代码段、数据段映射进内存，建立栈，跳到入口（通常先到 `_start`，再由 C 运行库调用 `main`），进程开始执行。

### 每一步最容易错的地方

- **`.o` 里已经是机器码**。别以为「汇编」只是整理文本：`as` 已经把指令编码成字节，只是地址还没最终确定，所以要带重定位信息。链接不改指令的含义，只填地址、合并段。
- **头文件只在预处理阶段起作用**。`#include` 就是把头文件内容抄进来；所以头文件里一般只放声明，定义放进 `.c`，否则多个 `.o` 链接时会「重复定义」。
- **区分三种「错」**：
  - 语法错、类型错：编译器报错（`.c` → `.s` 阶段）；
  - 未定义符号：链接器报错（`undefined reference to ...`），说明声明了却没提供定义；
  - 运行错：编译链接都过了，程序运行时才崩（空指针、数组越界等）。

**例**：`gcc -c hello.c` 只做到 `.o`，此时 `main` 里调用的 `printf` 还没接上；`gcc hello.o` 去链接时会到 `libc` 里找，找到就成功。如果把 `printf` 写成 `prinf`，编译器只给隐式声明警告，链接器才会真正报 `undefined reference`。

**再例**：想知道某条 C 语句对应什么指令，用 `gcc -S -O1` 看 `.s`，或对可执行文件用 `objdump -d` 反汇编。考试里「给一段汇编判断语义」的题，就是这条链路的反方向。
