## 这一章要会什么

- 用 \(T=\dfrac{N\cdot \mathrm{CPI}}{f}\) 算执行时间与加速比，并解释为什么指令数变少不一定变快
- 说出 `gcc` 四个阶段各自的输入、输出与工具，判断一个文件里还剩什么没确定
- 拿到一条报错，能判断它是编译期、链接期还是运行期的问题
- 用时间局部性和空间局部性解释「循环为什么快」「按列遍历为什么慢」
- 把一句 C 拆成「地址计算 + 一条 load/store」，并指出比例因子从哪来

## 1.1 计算机系统的层次与抽象

### 冯·诺依曼机器的取指—译码—执行循环

:::定理
条件：计算机采用「存储程序」结构，指令和数据放在同一个存储器里。

CPU 反复执行「取指—译码—执行」，程序计数器 PC 指向下一条指令；改指令和改数据走的是同一套内存读写。
:::

什么时候用：解释「程序也是数据」、为什么可以把代码当字节复制、为什么缓冲区溢出能改写控制流。


:::注意
PC 增加的不是固定 1。x86 指令长度可变，PC 加的是当前指令的字节数；分支、`call`、`ret` 会直接改写 PC。
:::
### 从门电路到应用程序的抽象栈

:::定理
条件：要判断某个现象发生在哪一层。

自下而上大致是数字电路、微体系结构、指令集体系结构（ISA）、操作系统、汇编语言、高级语言、应用程序；ISA 是软硬件的分界。
:::

什么时候用：判断「同一份 C 能不能换台机器跑」「换 CPU 要不要重新编译」「同一份机器码能不能通用」。


:::注意
ISA 相同，机器码才通用；同一 ISA 可以有不同微体系结构（流水线深度、缓存大小不同），性能会差很多。抽象把下层藏起来，但调试性能问题时必须下钻一层。
:::
### 存储层次与两种局部性

:::定理
条件：程序的访存有重复、有聚集。

寄存器 → L1 → L2 → L3 → 主存 → 磁盘，越往下容量越大、越慢、每字节越便宜；时间局部性指刚访问的数据很可能再被访问，空间局部性指邻近地址很可能紧接着被访问。
:::

什么时候用：解释循环体为什么快、为什么按行遍历二维数组比按列快、为什么链表遍历比数组慢。


:::注意
缓存按块搬运（通常 64 字节），读一个 `int` 会连带搬来一整块。按列遍历时每步跨一整行，块里的其余字节用不上，空间局部性被破坏。
:::
### 性能公式与加速比

:::定理
条件：已知指令数 \(N\)、平均 CPI、主频 \(f\)。



\[
T=\frac{N\cdot \mathrm{CPI}}{f},\qquad S=\frac{T_{\text{旧}}}{T_{\text{新}}}.
\]
:::

什么时候用：给两组参数比较优化效果，或判断「减少指令数」是否真的划算。


:::注意
指令数和 CPI 往往此消彼长，必须乘起来比。主频 \(2.5\,\mathrm{GHz}\) 是 \(2.5\times10^{9}\) 周期/秒。例：\(N=5.0\times10^{9}\)、CPI \(=1.6\)、\(f=2.5\,\mathrm{GHz}\) 时 \(T=3.2\,\mathrm{s}\)；优化后 \(N=4.0\times10^{9}\)、CPI \(=2.0\)，\(T\) 仍是 \(3.2\,\mathrm{s}\)，加速比为 1。
:::
## 1.2 程序的一生：从 C 到可执行文件

### 预处理、编译、汇编、链接四阶段

:::定理
条件：一份 `hello.c` 要变成可执行文件。

四个阶段的输入输出如下。

```
hello.c --预处理 gcc -E--> hello.i --编译 gcc -S--> hello.s
        --汇编 gcc -c--> hello.o --链接 ld--> hello
```
:::

什么时候用：看编译选项、判断 `.i`、`.s`、`.o` 各是什么、解释为什么要分文件编译。


:::注意
`.i` 还是 C 文本，`.s` 是汇编文本，`.o` 已经是机器码加元数据。头文件只在预处理阶段被「抄进来」，它本身不参与编译。
:::
### `.o` 文件里的符号表与重定位

:::定理
条件：源文件调用了别的文件或库里的函数。

`.o` 里的调用地址先留空，记在重定位表；符号表记录本文件定义的符号和引用的未定义符号；链接时解析符号、填地址、合并段。
:::

什么时候用：解释 `undefined reference to ...`（声明了没定义）和 `multiple definition`（多个 `.o` 都定义了同一符号）。


:::注意
头文件里放声明、`.c` 里放定义；函数定义前加 `static` 会让符号只在文件内可见，能避免重名。声明不产生定义。
:::
### 编译期、链接期、运行期三类错误

:::定理
条件：程序出错，要定位到哪个阶段。

语法错、类型错在编译期；未解析符号、重复定义在链接期；空指针、数组越界、除零在运行期。
:::

什么时候用：读报错信息、决定改头文件还是改源码。


:::注意
把 `printf` 拼成 `prinf`，编译器可能只给隐式声明警告，链接器才报 `undefined reference`。所以「能编译」不等于「能链接」，「能链接」不等于「能跑对」。
:::
### 用 `-S` 与 `objdump -d` 反查语义

:::定理
条件：给一段汇编要说出它对应哪句 C，或反过来。

`gcc -S -O1` 看编译器生成的汇编；`objdump -d` 反汇编已有可执行文件；`gcc -c` 只到目标文件。
:::

什么时候用：考试「读汇编写 C」题的标准入口，也是验证自己理解的手段。


:::注意
优化会重排、合并、删除代码。读汇编要按数据流看，不要按行号与 C 语句一一对应；`-O0` 与 `-O2` 的代码差别可能很大。
:::
## 常见问法与易错点

- 问「这段程序换台机器能不能直接跑」：先看 ISA，不是看 C 源码是否相同。
- 问「哪个阶段报错」：先看错误信息里的工具名，`cc1` 是编译器，`ld` 是链接器。
- 算性能题：先把 GHz 换成 \(10^{9}\)，再乘 CPI；只比较指令数是最常见的错。
- 「数组按列遍历慢」：答空间局部性，不要答「缓存太小」。
- 本章只到「地址计算 + 一条 load」。真正的寻址方式、栈帧、对齐在 3、4、5 章，别提前把 `D(Rb,Ri,S)` 混进概论题。
