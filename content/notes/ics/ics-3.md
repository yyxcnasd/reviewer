## 3.1 汇编基础与寻址方式

### 16 个通用寄存器与 32 位写清零

条件：给一个寄存器名字，要判断它指向哪几位。

结论：`%rax`、`%rbx`、`%rcx`、`%rdx`、`%rsi`、`%rdi`、`%rbp`、`%rsp` 加 `%r8`–`%r15` 是 16 个通用寄存器；`%rax` 的 32/16/8 位别名是 `%eax`、`%ax`、`%al`。

什么时候用：读汇编时确认操作数宽度，解释 `movl $0, %eax` 为什么等于把整个 `%rax` 清零。

注意：写 32 位寄存器会把高 32 位清零，写 16 位或 8 位不会。`%esp` 虽然也是 `%rsp` 的 32 位别名，但它就是栈指针，不能当普通寄存器拿来算。

### AT&T 的源在前与长度后缀

条件：读或写一条 x86-64 汇编指令。

结论：AT&T 语法是 `op 源, 目的`；后缀 `b/w/l/q` 分别表示 1/2/4/8 字节；立即数写 `$0x10`，寄存器写 `%rax`，内存写 `(%rax)`。

什么时候用：把 C 语句和汇编对照，判断一条 `mov` 搬了几个字节。

注意：源和目的写反是最高频错误。`movq %rax, (%rdi)` 是「把 rax 存到 rdi 指向的地址」，不是反过来。后缀与寄存器宽度要一致，`movl` 配 `%eax`。

### `D(Rb,Ri,S)` 的四个部件

条件：内存操作数形如 `8(%rdi,%rsi,4)`。

结论：

\[
\text{地址}=R_b+R_i\cdot S+D,\qquad S\in\{1,2,4,8\}.
\]

什么时候用：数组元素、结构体成员、栈上局部变量的访问，都归结为这一条。

注意：比例因子只能是 1、2、4、8；`(%rdi,%rsi,4)` 里 `%rdi` 是基址、`%rsi` 是下标，别读反。偏移 \(D\) 是 32 位补码，可正可负。

### `mov` 访存与 `lea` 只算地址

条件：区分 `mov 8(%rax), %rbx` 与 `lea 8(%rax), %rbx`。

结论：`mov` 读地址 \(R_{rax}+8\) 处的内容；`lea` 只把 \(R_{rax}+8\) 这个数放进 `%rbx`，不访存，也不设置条件码。

什么时候用：反汇编里看到 `lea` 要能翻译成算术；看到 `mov` 要能判断是否真的读内存。

注意：`lea` 的括号仍按地址表达式计算，但不是解引用。`leaq (%rdi,%rdi,2), %rax` 是 `%rax = 3 * %rdi`，不是读内存。

### `leal 0xffffffff(%eax)` 也能做减法

条件：反汇编里出现 `leal` 后跟一个接近 \(2^{32}\) 的偏移。

结论：地址计算按 32 位回绕，\(\texttt{0xffffffff}\) 等价于 \(-1\)，所以

```
leal 0xffffffff(%eax), %ecx   # ecx = eax - 1
```

什么时候用：读懂编译器用 `lea` 做的加减、乘加、取负，这类指令在优化后的代码里非常常见。

注意：反汇编可能把负偏移显示成无符号大数；要按目的寄存器的宽度回绕理解，别把它当成一个巨大的正数。

### `movz`/`movs` 扩展与 `push`/`pop`

条件：窄值要放进宽寄存器，或要临时保存一个值。

结论：`movzbl` 把字节零扩展到 32 位，`movsbq` 把字节符号扩展到 64 位；`pushq` 先减 `%rsp` 再写，`popq` 先读再加 `%rsp`。

什么时候用：`char`、`short` 参与运算前的提升，函数传参，保存被调用者保存寄存器。

注意：扩展方向别混，`movsbq` 是 byte→quad；`pushq` 一次动 8 字节，`push` 后栈顶是刚压入的值。栈向低地址增长。

## 3.2 分支与循环

### 条件码 CF/ZF/SF/OF 与 `cmp`/`test`

条件：算术或逻辑指令之后要判断结果。

结论：`CF` 记无符号进位/借位，`ZF` 记结果为零，`SF` 记结果为负，`OF` 记有符号溢出；`cmp b, a` 计算 \(a-b\) 并设标志，`test b, a` 计算 \(a\&b\) 并设标志。

什么时候用：if、循环、`switch` 的边界检查，全部靠条件码加 `jcc`。

注意：`mov` 和 `lea` **不设置**条件码，别在它们之后直接 `jg`。`test %rax, %rax` 是判零、判负最常用的写法。

### 有符号 `jg` 与无符号 `ja` 的选表

条件：比较两个整数后要跳转。

结论：有符号用 `jg/jge/jl/jle`，无符号用 `ja/jae/jb/jbe`，`je/jne` 两种都行。

什么时候用：C 的 `int`、`long` 比较用有符号；指针、`size_t`、地址比较用无符号。

注意：\(-1\) 与 \(1\) 比较，有符号看是 \(-1<1\)，无符号看是 \(2^{64}-1>1\)，结论正好相反。汇编层没有类型，全看你选了哪条 `jcc`。

### if-else 的取反跳转

条件：C 写 `if (a <= b) { then } else { else }`。

结论：编译器常把条件取反，先跳到 `else`，再顺序执行 `then`；两条路径最后汇合到同一个标签。

什么时候用：读反汇编里的 `.L2`、`.L3` 标签，判断哪一块对应 `then`。

注意：`jle .L2` 跳到 `else`，说明「\(a\le b\) 时执行 then」；条件取反后跳转是正常写法，不要以为跳转目标就是 then。

### while、for、do-while 的三种循环骨架

条件：给一段循环的 C 代码，要写出或读懂汇编骨架。

结论：`while`、`for` 先测试后执行，可能一次都不执行；`do-while` 先执行后测试，至少执行一次；编译器常把循环变量改成递减到 0，用 `jne` 收尾，省一条比较。

什么时候用：读循环反汇编、算循环执行次数、判断循环是否至少执行一次。

注意：`for (i = 1; i <= n; i++)` 与 `for (i = n; i > 0; i--)` 的边界条件不同，源程序改一个等号，汇编里的比较指令和初值都要跟着变。

### `switch` 跳转表与 `jmp *.L4(,%rdi,8)`

条件：`switch` 的 `case` 值比较密集。

结论：编译器生成一张跳转表，用 `jmp *.L4(,%rdi,8)` 一次跳过去，时间复杂度 \(O(1)\)；前面通常有 `cmp $n, %rdi; ja default` 做边界检查。

什么时候用：读 `switch` 反汇编、判断编译器是否生成了跳转表、解释为什么 `switch` 比一串 `if-else` 快。

注意：边界检查用无符号 `ja`，既查上界又排除负数。表项可能是 8 字节绝对地址，也可能是 32 位相对偏移；后者要先 `movslq` 取符号扩展的偏移，再与表基址相加，两种形式都要会读。

## 常见问法与易错点

- 问「这条 `mov` 读了几字节」：看后缀和目的寄存器宽度，`movq` 是 8 字节。
- 问「`lea` 在这里干什么」：先当算术算一遍，绝大多数 `lea` 都在做乘加，不是取地址。
- 问「为什么用 `ja` 不用 `jg`」：看操作数有没有符号，指针和 `size_t` 必须用无符号跳转。
- 问「`switch` 的复杂度」：密集 `case` 是 \(O(1)\) 跳转表，稀疏 `case` 退化成比较链或二分。
- 读汇编不要逐行硬翻 C，先找 `%rsp` 变化确认栈帧，再找条件码和跳转确认控制流。
