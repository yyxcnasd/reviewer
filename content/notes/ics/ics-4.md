## 4.1 栈帧与调用约定

### 栈与 call/ret

栈向低地址增长，`%rsp` 指向栈顶。

- `pushq %rbx`：先把 `%rsp` 减 8，再把 `%rbx` 存入栈顶；
- `popq %rbx`：先从栈顶读出，再把 `%rsp` 加 8；
- `call f`：把**返回地址**（`call` 的下一条指令的地址）压栈，然后跳到 `f`；
- `ret`：从栈顶弹出返回地址，跳回去。

**最容易错的一步**：`call` 之后、刚进入被调用函数时，栈顶已经是返回地址，`%rsp` 比调用前小了 8。所以「函数入口处 `%rsp % 16 = 8`」——后面所有对齐规则都是从这来的。

### 参数传递（System V AMD64）

前 6 个整型/指针参数依次放在 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`，浮点参数用 `%xmm0`–`%xmm7`。超过 6 个的整型参数**从右往左**压栈，返回值放在 `%rax`（更大的整数用 `%rax:%rdx`）。

进入被调用函数、还没执行 `pushq %rbp` 时，栈的布局是：

| 地址 | 内容 |
| --- | --- |
| `0(%rsp)` | 返回地址 |
| `8(%rsp)` | 第 7 个参数 |
| `16(%rsp)` | 第 8 个参数 |

所以执行 `pushq %rbp; movq %rsp, %rbp` 之后，返回地址在 `8(%rbp)`，第 7 个参数在 `16(%rbp)`，第 8 个在 `24(%rbp)`。

**例**：进入函数时 `%rsp = 0x7fffffffe008`，则返回地址在 `0x7fffffffe008`；`pushq %rbp` 把旧 `%rbp` 存到 `0x7fffffffe000`，然后 `%rbp = 0x7fffffffe000`。于是第 7 个参数在 `0x7fffffffe010`，第 8 个在 `0x7fffffffe018`。这类「给一个 `%rsp` 求各参数地址」的题，只要记住「返回地址在 0，参数从 8 开始」就不会错。

### 谁该保存寄存器

寄存器分两类：

- **调用者保存**（caller-saved）：`%rax %rcx %rdx %rsi %rdi %r8`–`%r11`。调用别人之后，里面的值可能被改掉，想保留就得自己提前存起来。
- **被调用者保存**（callee-saved）：`%rbx %rbp %r12`–`%r15`。被调用函数如果要用，必须先保存、返回前恢复，保证调用者看到的值不变。

**最容易错的一步**：在函数里用了 `%rbx` 却没 `push`/`pop`。这会悄悄改坏调用者的数据，表现为「程序在别处莫名出错」，是缓存区、递归类题目常见的坑点。

### 栈帧与 16 字节对齐

典型函数的开头和结尾：

```
f:
    pushq %rbp            # 保存调用者的 rbp
    movq %rsp, %rbp       # 建立当前帧基址
    subq $32, %rsp        # 给局部变量和临时值留空间（16 的倍数）
    ...
    leave                 # 等价于 movq %rbp, %rsp; popq %rbp
    ret
```

**为什么 `sub` 的量必须是 16 的倍数**：调用 `call` 前 `%rsp` 必须满足 `%rsp % 16 = 0`（ABI 要求）。进入函数时 `%rsp % 16 = 8`，`push %rbp` 后变成 0，再减一个 16 的倍数，调用下一个函数时仍然对齐。局部变量需要 \(N\) 字节时，`sub` 取「不小于 \(N\) 的最小 16 的倍数」。

## 4.2 局部变量与递归

### 局部变量放在哪

- 数量少、不取地址的局部变量：直接放寄存器；
- 数组、结构体、需要取地址的变量：放栈帧里；
- 编译器会重排、合并局部变量的位置，所以「C 里声明的顺序」不等于「栈上的顺序」。

### 递归与栈

每次递归调用都新建一个栈帧，所以栈深度等于递归深度。以

```c
long sum(long n) {
    if (n <= 0) return 0;
    return n + sum(n - 1);
}
```

为例，典型汇编是

```
sum:
    testq %rdi, %rdi
    jle .L2
    pushq %rbx
    movq %rdi, %rbx
    leaq -1(%rdi), %rdi
    call sum
    addq %rbx, %rax
    popq %rbx
    ret
.L2:
    movl $0, %eax
    ret
```

**为什么用 `%rbx`**：递归调用 `sum` 会覆盖调用者保存寄存器（包括 `%rcx`），而 `%rbx` 是被调用者保存的，`sum` 自己负责保存和恢复，所以把 `n` 放在 `%rbx` 里最省事。

**最容易错的一步**：算递归的栈深度。`sum(3)` 会依次调用 `sum(2)`、`sum(1)`、`sum(0)`，最深时栈上同时有 4 个返回地址、3 个保存的 `%rbx`（`sum(0)` 立刻返回，还没 `push`）。

**递归 vs 迭代**：递归的栈开销是 \(O(n)\) 空间。`sum(1000000)` 若每层占 32 字节，栈就要约 \(32\ \text{MB}\)，而默认栈大小通常 8 MB，结果就是栈溢出。尾递归在 `-O2` 下可能被优化成循环（复用同一个栈帧）。
