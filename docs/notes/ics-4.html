4.1 栈帧与调用约定

call 与 ret 压入返回地址

定理

条件：发生一次函数调用。

call f 把返回地址（call 的下一条指令的地址）压栈，然后跳到 f；ret 从栈顶弹出返回地址，跳回去。刚进入 f 时，返回地址在 0(%rsp)，%rsp 比调用前小 8。

什么时候用：算栈帧布局、定位缓冲区溢出要覆盖的返回地址、解释递归为什么占栈。

注意

压的是「下一条指令」的地址，不是 call 自己的地址。ret 只做「弹地址 + 跳转」，不检查这个地址是否合法——这正是溢出攻击能劫持控制流的原因。

六个参数寄存器与栈上第 7、8 个参数

定理

条件：函数参数超过 6 个整型/指针参数。

前 6 个依次放 %rdi、%rsi、%rdx、%rcx、%r8、%r9；浮点参数用 %xmm0–%xmm7；多出来的整型参数从右往左压栈；返回值在 %rax。

什么时候用：写或读函数调用的汇编，求某个参数在栈上的位置。

注意

进入函数、还没 pushq %rbp 时，0(%rsp) 是返回地址，8(%rsp) 是第 7 个参数。执行 pushq %rbp; movq %rsp, %rbp 之后，返回地址在 8(%rbp)，第 7 个参数在 16(%rbp)，第 8 个在 24(%rbp)。

%rsp % 16 = 8 与栈帧 16 字节对齐

定理

条件：ABI 要求调用函数前栈指针对齐。

call 之前 %rsp % 16 = 0；call 压入 8 字节返回地址，所以进入函数时 %rsp % 16 = 8；pushq %rbp 后变成 0；此后 subq 的量取 16 的倍数，才能保证下一次 call 仍然对齐。

什么时候用：算栈帧大小、解释「局部变量只要 20 字节，为什么 subq $32」。

注意

局部变量需要 NNN 字节时，sub 取不小于 NNN 的最小 16 的倍数。对齐被破坏时，调用用了 SSE 的库函数可能直接崩，症状往往与「栈上某个值」毫无关系。

调用者保存与被调用者保存寄存器

定理

条件：函数里要用寄存器保存一个值，且中间可能调用别的函数。

caller-saved 是 %rax、%rcx、%rdx、%rsi、%rdi、%r8–%r11，调用别人后值可能被改；callee-saved 是 %rbx、%rbp、%r12–%r15，被调用函数要用就必须先保存、返回前恢复。

什么时候用：写汇编函数决定 push/pop 哪些寄存器；读反汇编判断某个值为什么放在 %rbx。

注意

在函数里用了 %rbx 却没 push/pop，会悄悄改坏调用者的数据，程序可能在别处莫名出错。编译器把「跨调用还要保留的值」优先放 callee-saved 寄存器，就是这个原因。

pushq %rbp; movq %rsp, %rbp 与 leave

定理

条件：函数需要建立和拆除栈帧。

pushq %rbp 保存调用者的帧基址，movq %rsp, %rbp 建立当前帧，局部变量用 -8(%rbp)、-16(%rbp) 这类负偏移访问；leave 等价于 movq %rbp, %rsp; popq %rbp。

f:
    pushq %rbp            # 保存调用者的帧基址
    movq %rsp, %rbp       # 建立当前帧
    subq $32, %rsp        # 局部变量区，16 的倍数
    ...
    leave                 # movq %rbp, %rsp; popq %rbp
    ret                   # 弹出返回地址

什么时候用：读函数开头结尾，算局部变量相对 %rbp 的偏移。

注意

-O2 常省略帧指针，改用 %rsp 相对寻址，此时不能假设 %rbp 是帧基址；看到函数里没有 push %rbp 并不意味着没有栈帧。

4.2 局部变量与递归

局部变量放寄存器还是栈

定理

条件：函数里有局部变量。

数量少、不取地址、不跨函数调用保留的变量放寄存器；数组、结构体、取过地址的变量、volatile 变量放栈帧。

什么时候用：读汇编判断变量在寄存器还是内存，解释「取地址迫使变量进栈」。

注意

编译器会重排、合并局部变量，C 里的声明顺序不等于栈上顺序；两个变量可能共用一个栈槽。

递归的栈深度

定理

条件：递归函数每层都有自己的栈帧。

栈深度等于递归深度，每层至少占「返回地址 8 字节 + 保存的寄存器 + 局部变量」，并按 16 字节对齐向上取整。

什么时候用：估算递归的空间开销、判断会不会栈溢出。

注意

默认栈通常 8 MB，每层 32 字节时约 25 万层就耗尽。递归的空间复杂度是 O(n)O(n)O(n)，不是「不占空间」。

sum(n) 递归汇编里的 %rbx

定理

条件：return n + sum(n - 1) 这种递归。

n 要跨递归调用保留，编译器把它放进 callee-saved 的 %rbx，进入时 pushq %rbx，返回前 popq %rbx；开头用 testq %rdi, %rdi; jle 处理 n <= 0 的基线。

什么时候用：读递归的反汇编，解释为什么这里用 %rbx 而不是 %rcx。

注意

%rcx 是 caller-saved，递归返回后值可能已被改。sum(3) 最深时栈上有 4 个返回地址、3 个保存的 %rbx，因为 sum(0) 立刻返回、还没执行 push。

栈溢出与尾递归优化

定理

条件：递归深度非常大。

每层 32 字节、默认 8 MB 栈时，约 25 万层就会栈溢出；尾递归在 -O2 下可能被改写成循环，复用同一个栈帧。

什么时候用：解释大 n 递归的段错误、判断能否靠优化解决。

注意

不是所有递归都能尾递归优化。n + sum(n-1) 返回后还要做加法，不能直接复用帧；改写成「累积参数 + 尾调用」后才可能被优化。

常见问法与易错点

  • 问「返回地址在哪」：进入函数时在 0(%rsp)；push %rbp 后在 8(%rbp)。两套坐标别混。
  • 问「第 7 个参数在哪」：未建帧时 8(%rsp)，建帧后 16(%rbp)。
  • 问「为什么 subq $32 不是 $24」：16 字节对齐，取不小于需求的最小 16 的倍数。
  • 问「用 %rbx 为什么要 push」：callee-saved，必须保证调用者看到的值不变。
  • 算递归栈深度时，别忘了返回地址和保存的寄存器，不能只数局部变量。
