程序的内存与安全

6.1 进程的内存布局

按课程要求这一节不考，只需记住一句话：一个进程的地址空间里有代码段、数据段、栈和堆几块区域，栈在高地址、向低地址增长。下面直接进入 6.2。

6.2 缓冲区溢出

栈帧里的危险邻居

回忆函数调用：局部数组放在栈帧里，返回地址在 8(%rbp)。数组如果写得比分配的长度多，就会往高地址方向依次覆盖：相邻局部变量 → 保存的 %rbp → 返回地址。

顺序很重要，因为 ret 只做一件事：从栈顶弹出 8 个字节当地址跳过去。返回地址被改，控制流就被劫持。

一个例子

void echo(void) {
    char buf[16];
    gets(buf);
    puts(buf);
}

gets 不检查长度，输入多长就往 buf 里写多长。典型汇编是

echo:
    pushq %rbp
    movq %rsp, %rbp
    subq $16, %rsp        # buf 从 rbp-16 开始
    movq %rsp, %rdi
    call gets
    movq %rsp, %rdi
    call puts
    leave
    ret

buf 占 rbp-16 到 rbp-1，再往上 8 字节是保存的 %rbp，再往上 8 字节是返回地址。所以输入的第 25–32 个字节会改写返回地址：

输入偏移 覆盖的位置
0–15 buf 本身
16–23 保存的 %rbp
24–31 返回地址

最容易错的一步：算错「覆盖到返回地址要多少字节」。必须先把 buf 的大小、保存的 %rbp 的 8 字节都算进去；顺序差一个位置，构造出来的输入就完全失效。

攻击怎么发生

精心构造输入，把返回地址改成一段恶意代码（shellcode）的地址，或者改成进程里已有函数（例如 system）的地址，ret 时 CPU 就跳到那里执行。地址要按小端字节序写（x86-64 低字节在前），这是构造溢出字符串时最容易写反的一步。

三层防御，各挡一种

  1. 栈保护（canary）：在局部变量和返回地址之间放一个随机值，函数返回前检查它是否被改。溢出必须连续写，一定会踩坏 canary，程序调用 __stack_chk_fail 终止。开关是 -fstack-protector。
  2. 不可执行栈（NX / DEP）：栈所在内存页标记为不可执行，注入的 shellcode 一跑就崩。
  3. ASLR：随机化栈、堆、代码段的基址，攻击者猜不准要跳的目标地址。

此外还有安全函数与检查：用 fgets、strncpy 代替 gets、strcpy，打开编译器警告和 -D_FORTIFY_SOURCE。

注意：canary 只保护返回地址，挡不住「覆盖局部变量导致逻辑被改」这类问题；ASLR 只提高猜测难度，不是绝对安全。答题时问「哪种防御挡住了哪种攻击」，要一条对一条地说。
