一台机器有一级数据 cache，容量 32 KB32\ \text{KB}32 KB，cache line 为 64 B64\ \text{B}64 B；int 占 444 字节，二维数组按行优先存放：

int A[1024][1024];
long sum = 0;

考虑两种遍历方式：

/* 方式一：内层 j，行优先 */
for (int i = 0; i < 1024; i++)
    for (int j = 0; j < 1024; j++)
        sum += A[i][j];

/* 方式二：内层 i，列优先 */
for (int j = 0; j < 1024; j++)
    for (int i = 0; i < 1024; i++)
        sum += A[i][j];

(1) 分别估算两种方式的 cache 缺失率。

(2) 设每次命中花 111 个周期、每次缺失额外花 100100100 个周期，估算两种方式每个元素的平均周期数。

(3) 两种方式的总周期数之比是多少？

(4) 如何改写循环，使列优先的访问也能接近行优先的性能？说明理由。

提示+

先算一条 cache line 能装几个 int：64/4=1664/4=1664/4=16 个。行优先时内层沿行前进，相邻 16 次访问落在同一条 line 上；列优先时内层沿列前进，地址每次跳 1024×4=40961024\times4=40961024×4=4096 字节，一步跨过 646464 条 line。再看 cache 能不能装下这些 line。

解析（先自己做一遍再看）展开
答案

(1) 行优先缺失率 1/16=6.25%1/16=6.25\%1/16=6.25%，列优先接近 100%100\%100%；(2) 行优先每元素约 7.257.257.25 周期，列优先 101101101 周期；(3) 约 13.913.913.9 倍；(4) 用 16×1616\times1616×16 分块，使块内每行 16 个 int 正好占满一条 cache line

(1) 一条 cache line 64 B64\ \text{B}64 B，装 64/4=1664/4=1664/4=16 个 int。

方式一（行优先）：内层 jjj 每次加 1，地址加 4 字节。连续 16 次访问落在同一条 line 里，只有第一次缺失，后 15 次命中。所以缺失率

116=6.25%.\frac{1}{16}=6.25\%.161​=6.25%.

当前行只占 1024×4=4 KB=641024\times4=4\ \text{KB}=641024×4=4 KB=64 条 line，而 cache 有 32 KB/64 B=51232\ \text{KB}/64\ \text{B}=51232 KB/64 B=512 条 line，装得下一整行，下一行也不会把当前行挤掉。

方式二（列优先）：内层 iii 每次加 1，地址加 1024×4=4096 B=641024\times4=4096\ \text{B}=641024×4=4096 B=64 条 line。也就是说每访问一个元素，A[i][j] 与下一个元素 A[i+1][j] 落在完全不同的 line 上。

一列有 102410241024 个元素，需要 102410241024 条不同的 line；而 cache 只有 512512512 条 line。等外层 jjj 加 1、回到同一批元素附近时，早先的 line 已经被挤出 cache。所以几乎每次访问都缺失，缺失率接近

100%.100\%.100%.

(2) 平均周期数 = 命中时间 + 缺失率 × 缺失代价。

方式一：

1+0.0625×100=1+6.25=7.25 周期/元素.1+0.0625\times100=1+6.25=7.25\ \text{周期/元素}.1+0.0625×100=1+6.25=7.25 周期/元素.

方式二：

1+1×100=101 周期/元素.1+1\times100=101\ \text{周期/元素}.1+1×100=101 周期/元素.

(3) 数组共 1024×1024=1 048 5761024\times1024=1\,048\,5761024×1024=1048576 个元素。

1017.25≈13.9.\frac{101}{7.25}\approx13.9.7.25101​≈13.9.

方式二比方式一慢约 13.913.913.9 倍。两者的指令数几乎一样，差距全来自空间局部性：行优先把一条 line 的 16 个元素用满了，列优先每个元素都要重新搬一条 line。

(4) 用分块（blocking）：每次只处理 16×1616\times1616×16 的子块，块内按行访问。

for (int ii = 0; ii < 1024; ii += 16)
    for (int jj = 0; jj < 1024; jj += 16)
        for (int i = ii; i < ii + 16; i++)
            for (int j = jj; j < jj + 16; j++)
                sum += A[i][j];

这样内层 jjj 的 16 次访问正好落在一条 cache line（16×4=64 B16\times4=64\ \text{B}16×4=64 B）内；一个块只有 161616 条 line，完全装得进 512 条 line 的 cache，下一次用到时还在。缺失率回到约 1/161/161/16，每个元素约 7.257.257.25 个周期。

关键的那一步为什么能想到：先算「一条 line 装多少元素」和「相邻访问的步长」。行优先步长 4 字节 → line 被用满；列优先步长 4096 字节 → 每次换 line。再算「工作集大小 vs cache 容量」：列优先的工作集是 1024 条 line，大于 512 条，所以必然抖动。分块的思路就是把工作集缩到 cache 装得下。

常见错误展开

一是把列优先的缺失率估成 1/161/161/16——它每次访问都在不同的 line 上，根本没有复用。二是忘记用「工作集 102410241024 条 line 与 cache 512512512 条 line」比较，只看到 line 大小就下结论。三是把两种方式的总周期比算成 100/1=100100/1=100100/1=100，忽略了命中时的 1 个周期。四是分块时取的块大小与 line 不匹配（比如取 8×88\times88×8），那样内层只用到半条 line，收益减半。
