对 n=512n=512n=512 的方阵乘法 C=A×BC=A\times BC=A×B（double，8 字节），机器有一级数据 cache：容量 32 KB32\ \text{KB}32 KB，cache line 64 B64\ \text{B}64 B，命中 111 个周期，缺失额外 100100100 个周期。只看 AAA、BBB 的读，忽略 CCC 的写、TLB 与多核影响。

朴素实现：

for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) {
        double s = 0;
        for (int k = 0; k < n; k++)
            s += A[i][k] * B[k][j];
        C[i][j] = s;
    }

(1) 分别估算 AAA、BBB 的 cache 缺失率，以及总的缺失率。

(2) 求每次访存的平均周期数与矩阵乘的总周期数。

(3) 改用 32×3232\times3232×32 的分块（块内三层循环，保证三个 32×3232\times3232×32 的小块能同时放进 cache），重新估算缺失率、总周期数与矩阵乘的加速比。

(4) 整个程序运行 10 s10\ \text{s}10 s，其中 7 s7\ \text{s}7 s 花在矩阵乘上。分块后整体加速比是多少？若希望整体加速 333 倍，矩阵乘的缺失率至少要降到多少？单级 32×3232\times3232×32 分块能做到吗？

提示+

先算一条 line 装几个 double：64/8=864/8=864/8=8。朴素三重循环里，内层 kkk 让 A[i][k]A[i][k]A[i][k] 沿行前进（空间局部性好），而 B[k][j]B[k][j]B[k][j] 每次跨 n×8=4096n\times8=4096n×8=4096 字节（不同行）。分块的思路是让三个块的工作集 3×32×32×8 B3\times32\times32\times8\ \text{B}3×32×32×8 B 小于 cache 容量。

答案

朴素顺序：A 缺失率 1/81/81/8、B 约 100%100\%100%，总缺失率 56.25%56.25\%56.25%，约 1.54×10101.54\times10^{10}1.54×1010 周期；32×32 分块后约 12.5%12.5\%12.5%、3.62×1093.62\times10^{9}3.62×109 周期，矩阵乘加速比约 4.254.254.25；整体（10 s 中 7 s 是矩阵乘）加速比约 2.152.152.15，要整体 3 倍需缺失率降到约 1.7%1.7\%1.7%，单级 32×32 分块做不到

(1) 一条 line 装 64/8=864/8=864/8=8 个 double。

访问 AAA：内层 kkk 递增，A[i][k] 在行内连续，每 8 次访问落在同一条 line 上，缺失率

18=12.5%.\frac{1}{8}=12.5\%.81​=12.5%.

访问 BBB：内层 kkk 递增，B[k][j] 的地址每次加 512×8=4096 B=64512\times8=4096\ \text{B}=64512×8=4096 B=64 条 line，即每一步都换一条新 line。对固定的 jjj，k=0..511k=0..511k=0..511 要碰 512 条不同的 line；cache 一共只有 32 KB/64 B=51232\ \text{KB}/64\ \text{B}=51232 KB/64 B=512 条 line，而 AAA 的当前行还要占 64 条，工作集超过容量，BBB 的 line 在下次用到之前基本都被挤掉，所以 BBB 的缺失率接近

100%.100\%.100%.

总缺失率：内层循环每次迭代读 AAA、BBB 各一次，两者访问次数相同，所以

缺失率=12×18+12×1=56.25%.\text{缺失率}=\frac{1}{2}\times\frac{1}{8}+\frac{1}{2}\times1=56.25\%.缺失率=21​×81​+21​×1=56.25%.

(2) 总访问次数：每次 (i,j,k)(i,j,k)(i,j,k) 读 2 个元素，共

2n3=2×5123≈2.68×108.2n^{3}=2\times512^{3}\approx2.68\times10^{8}.2n3=2×5123≈2.68×108.

每次访问的平均周期数

1+0.5625×100=57.25,1+0.5625\times100=57.25,1+0.5625×100=57.25,

总周期数

2.68×108×57.25≈1.54×1010.2.68\times10^{8}\times57.25\approx1.54\times10^{10}.2.68×108×57.25≈1.54×1010.

为什么想到：把访问拆成"顺序流"（AAA）和"跨行流"（BBB）分别算缺失率，再按访问次数加权；缺失代价只有乘上缺失率才是平均代价。

(3) 32×3232\times3232×32 的块：三个块各 32×32×8=8 KB32\times32\times8=8\ \text{KB}32×32×8=8 KB，合计 24 KB<32 KB24\ \text{KB}<32\ \text{KB}24 KB<32 KB，能同时驻留。

块内按行访问，一条 line 的 8 个元素连续用完，AAA、BBB 的缺失率都降到约 1/8=12.5%1/8=12.5\%1/8=12.5%。总缺失率约 12.5%12.5\%12.5%，每次访问平均周期数

1+0.125×100=13.5,1+0.125\times100=13.5,1+0.125×100=13.5,

总周期数

2.68×108×13.5≈3.62×109.2.68\times10^{8}\times13.5\approx3.62\times10^{9}.2.68×108×13.5≈3.62×109.

矩阵乘的加速比

1.54×10103.62×109≈4.25.\frac{1.54\times10^{10}}{3.62\times10^{9}}\approx4.25.3.62×1091.54×1010​≈4.25.

(4) Amdahl 定律：矩阵乘从 7 s7\ \text{s}7 s 降为

7/4.25≈1.65 s,7/4.25\approx1.65\ \text{s},7/4.25≈1.65 s,

其余 3 s3\ \text{s}3 s 不变，总时间

3+1.65=4.65 s,整体加速比=104.65≈2.15.3+1.65=4.65\ \text{s}, \qquad \text{整体加速比}=\frac{10}{4.65}\approx2.15.3+1.65=4.65 s,整体加速比=4.6510​≈2.15.

若要整体加速 333 倍，总时间必须降到 10/3≈3.33 s10/3\approx3.33\ \text{s}10/3≈3.33 s，留给矩阵乘的只有

3.33−3=0.33 s,3.33-3=0.33\ \text{s},3.33−3=0.33 s,

即矩阵乘要加速 7/0.33≈217/0.33\approx217/0.33≈21 倍。对应总周期数

1.54×1010×0.337≈7.3×108,1.54\times10^{10}\times\frac{0.33}{7}\approx7.3\times10^{8},1.54×1010×70.33​≈7.3×108,

折合每次访问

7.3×1082.68×108≈2.73 周期,\frac{7.3\times10^{8}}{2.68\times10^{8}}\approx2.73\ \text{周期},2.68×1087.3×108​≈2.73 周期,

于是缺失率要降到

2.73−1100≈1.7%.\frac{2.73-1}{100}\approx1.7\%.1002.73−1​≈1.7%.

单级 32×3232\times3232×32 分块只把缺失率降到 12.5%12.5\%12.5%，远远不够；需要多级分块（寄存器分块 + cache 分块）、软件预取、或更大的 cache。注意 Amdahl 给出的上限是"矩阵乘完全不花时间"时整体 10/3=3.3310/3=3.3310/3=3.33 倍，所以 333 倍在原理上可达，但需要把缺失率压到 1.7%1.7\%1.7% 以下。

为什么想到：整体加速比先看"被优化部分占多大比例"（7/107/107/10），再看该部分能被加速多少；要求整体 3 倍时，先用 Amdahl 反推被优化部分剩余的时间预算，再把它翻译成缺失率。

常见错误展开

一是把 BBB 的缺失率估成 1/81/81/8——B[k][j]B[k][j]B[k][j] 沿列走，每次跨 4096 字节，一条 line 里其余 7 个元素在当前内层循环根本用不到。二是忽略 AAA 也要占 cache，直接说 BBB 的 512 条 line 刚好放得下；实际加上 AAA 的行就超容量。三是算平均周期时把缺失代价 100100100 直接加在每次访问上，忘记乘缺失率。四是整体加速比用 7/4.25=1.657/4.25=1.657/4.25=1.65 当答案，忘记加上未优化的 3 s3\ \text{s}3 s；或者把"整体 3 倍"直接理解成"矩阵乘 3 倍"。
