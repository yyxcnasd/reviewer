数组与结构体 · 计算题

计算机系统概论 计算题 难度 自编 投稿：自编
导出这道题 ICS-047 · ←→ 翻题 · E 展开 · D 记已做

下面三组声明里，int 占 4 字节，二维数组按行优先存放。按本课程的约定，把 a 的 3×4=123\times4=123×4=12 个 int 看成一块连续的 48 字节内存：

int a[3][4];
int b[12];

int *p = &a[0][0];   /* 按上述约定，p 可在这 12 个 int 上做指针算术 */
int *q = &a[2][3];
int *r = b;          /* 指向一维数组 b 的首元素 */

回答：

(1) sizeof(a)、sizeof(a[0]) 各是多少？a[1] + 1 的类型是什么，指向哪个元素？

(2) q - p 和 &a[1][2] - p 的值分别是多少？它们的单位是字节还是元素？

(3) p[7] 是哪个元素？用二维下标写出它。

(4) 判断下面的表达式是否合法、是否属于未定义行为（UB），并说明理由：

r + 12;      /* (1) */
r + 13;      /* (2) */
*(r + 12);   /* (3) */
*(r + 11);   /* (4) */
a[3][0];     /* (5) */

(5) C 标准为什么允许"指向数组末尾后一个位置"的指针（one-past-the-end），却不允许多走一个？

提示+

二维数组 a[3][4] 的类型是"3 个 int[4] 的数组"，在内存里是 12 个连续的 int。a[i] 退化为指向该行首元素的 int*。

二维下标与一维序号的关系：a[i][j] 就是第 4i+j4i+j4i+j 个 int。

指针相减得到"元素个数"；判断指针算术是否合法时，看它指向的那个数组对象有多大——b 是 12 个 int 的数组，这是判断 (1)–(4) 的基准。

解析（先自己做一遍再看）展开
答案

(1) sizeof(a)=48，sizeof(a[0])=16，a[1]+1 是指向 a[1][1] 的 int*；(2) q-p=11，&a[1][2]-p=6，单位是元素（int）不是字节；(3) p[7] 就是 a[1][3]；(4) r+12、*(r+11) 合法；r+13、*(r+12) 是未定义行为；a[3][0] 越界访问是 UB；(5) one-past 合法是为了支持半开区间与循环边界

(1) a 是 3×43\times43×4 的 int 数组：

sizeof(a)=3×4×4=48 字节,sizeof(a[0])=4×4=16 字节.\texttt{sizeof}(a)=3\times4\times4=48\ \text{字节},\qquad \texttt{sizeof}(a[0])=4\times4=16\ \text{字节}.sizeof(a)=3×4×4=48 字节,sizeof(a[0])=4×4=16 字节.

a[1] 的类型是 int[4]，在表达式里退化为指向首元素的 int*，所以 a[1] + 1 是 int*，指向 a[1][1]（相对 a 的字节偏移 16+4=2016+4=2016+4=20）。

(2) 把二维下标映射到一维序号：

a[i][j] ⟷ 4i+j.a[i][j]\ \longleftrightarrow\ 4i+j.a[i][j] ⟷ 4i+j.

p 指向 a[0][0]a[0][0]a[0][0]（序号 0），q 指向 a[2][3]a[2][3]a[2][3]（序号 4×2+3=114\times2+3=114×2+3=11），所以

q−p=11.q-p=11.q−p=11.

同理 a[1][2]a[1][2]a[1][2] 的序号是 4×1+2=64\times1+2=64×1+2=6，所以 &a[1][2] - p = 6。指针相减的单位是元素（这里是 int），不是字节；要字节差才乘 sizeof(int)。

(3) p[7] 等价于 *(p+7)，序号 7=4×1+37=4\times1+37=4×1+3，即

a[1][3].a[1][3].a[1][3].

(4) 判断基准是"指针指向的数组对象有多大"：b 有 12 个元素，合法下标 0–11，末尾后一个位置是 b+12。

  • (1) r + 12：指向 b 的 one-past-the-end，合法，可以参与比较、相减，但不能解引用。
  • (2) r + 13：越过 one-past，指针算术本身就越界，属于 UB（不需要解引用就已经 UB）。
  • (3) *(r + 12)：解引用 one-past 指针，UB。
  • (4) *(r + 11)：b[11]，在数组范围内，合法。
  • (5) a[3][0]：a 的行下标只能是 0–2，a[3] 已经是越界访问，UB。

关键的一步是区分"指针值合法"与"解引用合法"：one-past 指针可以存在、可以比较，但不指向任何对象，读写它就是 UB。

(5) one-past 让"半开区间"成为可能：C 里区间约定为 [begin, end)，end 正是最后一个元素的下一个位置。这样循环可以写成

for (int *it = r; it != r + 12; ++it) { ... }

不必在每次迭代里额外判断"是不是最后一个"。如果连 one-past 都不允许，end 指针就无法表达，循环边界要么多算一次、要么引入额外条件分支。

但不允许再往后走：r+13 没有对应的数组对象，标准无法保证其算术结果有意义（某些平台上地址计算可能溢出或触发陷阱），因此规定为 UB。

严格按 ISO C 的字面规定，&a[0][0] 的指针算术边界只覆盖 a[0] 这一行（4 个 int）；把它当连续 12 个 int 使用是编译器与教材（含 CSAPP）普遍采用的约定，本课程的偏移计算也按这个约定。真要严格跨行访问，用 (char *)a 做字节算术，或直接用一维数组 b。

常见错误展开
  • 把 q - p 当成字节差 11×4=4411\times4=4411×4=44。指针相减的单位是元素个数；字节差要自己乘 sizeof(int)。
  • 把 a[1] + 1 的类型说成 int** 或 int[4]。a[1] 退化为 int*，加 1 仍是 int*。
  • 认为 r + 13 "只要不解引用就没问题"。指针算术越界本身就是 UB。
  • 把 *(r + 12) 当成合法，因为"它只是最后一个元素后面一个"。one-past 可以取地址，不能读。
  • 认为二维数组 a 的元素是"行"，所以 p+1 跳到下一行。p 是 int*，p+1 是下一个 int；只有 a+1（类型 int(*)[4]）才跳一行。
