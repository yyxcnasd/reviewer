函数调用 · 综合题

计算机系统概论 综合题 难度 自编 投稿：自编
导出这道题 ICS-068 · ←→ 翻题 · E 展开 · D 记已做

函数

long f(long n, long a, long b, long c, long d, long e, long g, long h) {
    long vla[n];        /* 变长数组 */
    vla[0] = a + h;
    return vla[0];
}

的汇编开头是

f:
    pushq   %rbp
    movq    %rsp, %rbp
    movq    %rdi, %rax          # rax = n
    salq    $3, %rax            # 8*n，long 占 8 字节
    addq    $15, %rax
    andq    $-16, %rax          # 向上取整到 16 的倍数
    subq    %rax, %rsp          # 动态分配
    movq    %rsp, %rcx          # vla 的起始地址
    ...
    leave
    ret

(1) 8 个参数里哪些通过寄存器传递、哪些在栈上？第 7、8 个参数相对 %rbp 的偏移分别是多少？

(2) 设进入 f 时 %rbp = 0x7fffffffe000。分别求 n = 5 与 n = 3 时 VLA 的起始地址和分配后的 %rsp。

(3) 若调用者传入 n = 2^{61}，会发生什么？为什么写 vla[1] 可能直接改写返回地址？

(4) addq $15 与 andq $-16 这一对指令在做什么？为什么栈帧大小必须是 16 的倍数？

(5) 函数返回时用 leave 恢复现场，动态分配的 VLA 大小并不固定，leave 为什么还能正确恢复 %rsp？

提示+

先数参数：整型/指针的前 6 个走寄存器，第 7 个起从右往左压栈，进入函数时栈顶是返回地址。VLA 的大小在运行期才确定，所以编译器用「乘元素大小、加 15、与 -16 相与」来算一个 16 字节对齐的字节数，再 sub 到 %rsp。

解析（先自己做一遍再看）展开
答案

前 6 个参数在 rdi/rsi/rdx/rcx/r8/r9，第 7、8 个在 16(%rbp)、24(%rbp)；n=5 时 VLA 起点为 0x7fffffffdfd0；n=3 时为 0x7fffffffdff0；n=2^61 时分配量算成 0，VLA 起点回到 %rbp，vla[1] 正好是返回地址

(1) 前 6 个参数依次在 %rdi、%rsi、%rdx、%rcx、%r8、%r9，所以 n、a、b、c、d、e 走寄存器；第 7 个 g、第 8 个 h 由调用者压栈。

进入函数时栈顶是返回地址，所以布局是：

0(%rbp) 8(%rbp) 16(%rbp) 24(%rbp)
地址 内容
保存的旧 %rbp
返回地址
第 7 个参数 g
第 8 个参数 h

为什么想到：先确认「函数入口时栈顶是返回地址、push %rbp 又占 8 字节」，再按参数顺序数到第 7 个，就能推出 16 和 24，不用死记。

(2) n=5：先算 8n=408n=408n=40，addq $15 得 555555，andq $-16 把低 4 位清零，得到 484848。于是

%rsp=0x7fffffffe000−48=0x7fffffffdfd0,\%rsp=0x7fffffffe000-48=0x7fffffffdfd0,%rsp=0x7fffffffe000−48=0x7fffffffdfd0,

VLA 起点就是 0x7fffffffdfd0。

n=3：8n=248n=248n=24，24+15=3924+15=3924+15=39，向下对齐到 16 的倍数得 323232：

%rsp=0x7fffffffe000−32=0x7fffffffdff0.\%rsp=0x7fffffffe000-32=0x7fffffffdff0.%rsp=0x7fffffffe000−32=0x7fffffffdff0.

注意 24 本身不是 16 的倍数，所以要多留 8 字节填充；这就是 addq $15 的作用——先加上「最大填充」，再整体向下对齐，等价于向上取整。

(3) n=261n=2^{61}n=261 时，salq $3 计算 8n=2648n=2^{64}8n=264，在 64 位寄存器里按模 2642^{64}264 回绕成 000。接着 addq $15 得 151515，andq $-16 得 000，于是 subq $0——没有分配任何栈空间，%rsp 仍等于 %rbp，VLA 起点也变成 %rbp。

此时写 vla[0] 写到 0(%rbp)，覆盖保存的旧 %rbp；写 vla[1] 写到 8(%rbp)，正好覆盖返回地址。leave 时 %rbp 被破坏、ret 时跳到被改写的地址——典型的 VLA 大小溢出导致的栈破坏。C 标准里 VLA 大小在计算中溢出是未定义行为，编译器不会替你做检查。

顺带一提，n=−1n=-1n=−1 也一样危险：8n=−88n=-88n=−8，加 15 得 7，对齐后为 0，同样不分配。

(4) 这一对指令做的是「把字节数向上取整到 16 的倍数」。对齐要求来自 ABI：执行 call 前 %rsp 必须满足 %rsp % 16 = 0。进入函数时 %rsp % 16 = 8，pushq %rbp 后变成 0，所以 sub 的量只要是 16 的倍数，后续调用其他函数时对齐仍然成立。

(5) leave 等价于

movq %rbp, %rsp
popq %rbp

它恢复的是帧基址而不是之前保存的 %rsp 值：%rbp 在函数开头就固定指向本帧的起点，VLA 无论分配了多大，%rsp 都可以直接拉回 %rbp。这也是为什么动态分配不需要额外保存旧 %rsp。

为什么想到：看到 push rbp; mov rsp,rbp 就知道 %rbp 是"锚点"；任何对 %rsp 的临时修改都可以在收尾时一次抹掉。

常见错误展开

一是把第 7、8 个参数算成 8(%rbp)、16(%rbp)，忘了 8(%rbp) 是返回地址。二是把 andq $-16 当成"只清低 4 位、不改变大小"，忽略它和 addq $15 配合才等于向上取整。三是以为 VLA 大小溢出时程序会崩溃或报错，实际上汇编照常执行、只是分配量为 0。四是认为 leave 能恢复 VLA 之前的 %rsp 是因为保存了旧值——它靠的是 %rbp 锚点。
