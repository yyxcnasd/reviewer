信息的表示与处理 · 综合题

计算机系统概论 综合题 难度 自编 投稿：自编
导出这道题 ICS-067 · ←→ 翻题 · E 展开 · D 记已做

单精度浮点执行下面的累加：

float s = 0.0f;
for (int i = 0; i < (1 << 25); i++)   /* 2^25 次 */
    s += 1.0f;

(1) 循环结束后 s 等于多少？

(2) 从第几次加法开始 s 不再变化？用 ulp 和舍入模式推导，并说明为什么此后永远不动。

(3) 把 float 换成 double，最终值是多少？停滞点出现在哪个数量级？

(4) 有人建议改用 Kahan 补偿求和来修复。请分析：在这个具体例子里 Kahan 能救回来吗？为什么？

提示+

先找 2242^{24}224 附近单精度的间距（ulp）：有效位 24 位，指数 E=24E=24E=24 时相邻浮点数的距离是 224−23=22^{24-23}=2224−23=2。再判断 224+12^{24}+1224+1 落在哪个格点上——它刚好是两个相邻浮点数的中点，这时要看默认舍入模式怎么处理中点。

解析（先自己做一遍再看）展开
答案

单精度下 s=16777216=224s=16777216=2^{24}s=16777216=224；第 167772171677721716777217 次加法起不再变化（2242^{24}224 处 ulp 为 222，224+12^{24}+1224+1 恰为中点，向偶数舍入回 2242^{24}224）；double 得 335544323355443233554432，停滞点在 2532^{53}253；Kahan 补偿在此例中无效

(1) 在 s<224s<2^{24}s<224 时，sss 的 ulp 不超过 1，加 1 是精确的，所以 sss 会严格按 1,2,…1,2,\dots1,2,… 增长；一旦到达 2242^{24}224，就进入停滞。最终

s=224=16 777 216.s=2^{24}=16\,777\,216.s=224=16777216.

(2) 224∈[224,225)2^{24}\in[2^{24},2^{25})224∈[224,225)，该区间的指数 E=24E=24E=24，单精度 ulp 为

ulp=2E−23=224−23=2.\text{ulp}=2^{E-23}=2^{24-23}=2.ulp=2E−23=224−23=2.

所以 2242^{24}224 附近可表示的数只有 2242^{24}224、224+22^{24}+2224+2、224+4,…2^{24}+4,\dots224+4,…。加 1 的精确结果是

224+1,2^{24}+1,224+1,

它恰好是 2242^{24}224 与 224+22^{24}+2224+2 的中点。默认舍入是「向偶数舍入」（round-to-even），中点上取尾数末位为 0 的那个：224=1.000…02×2242^{24}=1.000\ldots0_2\times2^{24}224=1.000…02​×224 的末位是 0，224+2=1.000…12×2242^{24}+2=1.000\ldots1_2\times2^{24}224+2=1.000…12​×224 的末位是 1，于是

224+1 ⟶ 224.2^{24}+1\ \longrightarrow\ 2^{24}.224+1 ⟶ 224.

加法结果仍是 2242^{24}224，下一次加 1 面对完全相同的局面，所以第 224+1=16 777 2172^{24}+1=16\,777\,217224+1=16777217 次加法起 sss 永远停在 2242^{24}224。理论上应得 225=33 554 4322^{25}=33\,554\,432225=33554432，实际少了整整一半。

为什么想到：浮点加法停滞的判据是「增量小于半个 ulp」，而这里增量 111 恰好等于半个 ulp，属于中点，必须再调用一次舍入规则（向偶数）才能判断，不能只说"被舍掉"。

(3) double 有效位 53 位，ulp 在 [253,254)[2^{53},2^{54})[253,254) 内才达到 2，而本循环最多加到 2252^{25}225，远小于 2532^{53}253，每次加 1 都精确：

s=225=33 554 432.s=2^{25}=33\,554\,432.s=225=33554432.

double 的停滞点要到 253≈9.0×10152^{53}\approx9.0\times10^{15}253≈9.0×1015 才开始（加 1 变成中点、向偶数舍入不动）。

(4) 救不回来。 Kahan 的写法是

float y = 1.0f - c;
float t = s + y;
c = (s - t) + y;
s = t;

在 s=224s=2^{24}s=224 时：y=1y=1y=1，t=s+1t=s+1t=s+1 舍入回 sss，于是 c=(s−t)+y=0+1=1c=(s-t)+y=0+1=1c=(s−t)+y=0+1=1。下一轮 y=1−c=0y=1-c=0y=1−c=0，t=s+0=st=s+0=st=s+0=s，c=(s−t)+0=0c=(s-t)+0=0c=(s−t)+0=0——补偿项被"清零"了，sss 始终是 2242^{24}224。Kahan 补偿的前提是「大数加小数时，被舍掉的部分能通过减法恢复」，但这里 t=st=st=s 与 sss 完全相等，减法拿不到任何信息，补偿失效。

正确做法是提高累加精度（用 double 累加再转换）或用整数累加（本例直接算 2252^{25}225），也可以用两两求和（pairwise）把同量级的数先相加。

常见错误展开

一是认为"浮点有误差"就直接给个近似值，不判断停滞点。二是把中点舍入说成"总是舍入到较大的数"或"总是截断"；默认是向偶数，此例恰好回到较小的 2242^{24}224。三是以为 sss 会涨到 2252^{25}225 只是误差小一点，实际上最大只到 2242^{24}224，差一倍。四是盲目相信 Kahan 万能：补偿项在"结果与加数完全相等"的极端情形会丢失信息。
