汇编语言与程序的机器级表示 · 概念题

计算机系统概论 概念题 难度 自编 投稿：自编
导出这道题 ICS-037 · ←→ 翻题 · E 展开 · D 记已做

C 函数 int less(float a, float b) { return a < b; } 的 a、b 分别放在 %xmm0、%xmm1。编译器生成的汇编是

less:
    comiss %xmm1, %xmm0
    setb   %al
    setnp  %dl
    andb   %dl, %al
    movzbl %al, %eax
    ret

回答：

（1）comiss 比较的是哪两个数？它设置哪些标志位？

（2）为什么不能只用 setb %al（把中间两条去掉）？

（3）当 a 为 NaN、b = 1.0f 时，CF、ZF、PF 各是什么？函数最终返回多少？

（4）如果函数改成 a > b，可以只用 comiss %xmm1, %xmm0; seta %al。为什么这里不需要再加 setnp？

（5）如果要判断 a == b，应该怎样组合 set 指令？

提示+
comiss 按「%xmm0 减 %xmm1」设置 ZF、PF、CF 三个标志。对普通数，小于、等于、大于分别对应 CF、ZF 的不同组合；但只要有一个操作数是 NaN，结果就是「无序」，此时 ZF=PF=CF=1。浮点比较的坑全在无序这一种情况上。

解析（先自己做一遍再看）展开
答案

（1）比较 %xmm0 中的 aaa 与 %xmm1 中的 bbb，按 a−ba-ba−b 设置 ZF、PF、CF；（2）NaN 时 CF=1，只用 setb 会错误地返回 1；（3）CF=ZF=PF=1，返回 0；（4）seta 要求 CF=0 且 ZF=0，无序时两者都是 1，自然为假；（5）sete 与 setnp 相与

关键的那一步为什么能想到。 整数比较只有三种结果（小于、等于、大于），浮点比较却多出第四种：无序（unordered）。comiss 用 ZF、PF、CF 三个标志编码四种情况，其中无序把三个标志全部置 1。因此判断「小于」时，CF=1 既可能是真的小于，也可能是无序，必须再用 PF=0 排除无序；而判断「大于」时条件 CF=0 且 ZF=0 本身就把无序（CF=1）排除掉了。抓住「无序时三个标志全 1」这一点，就能看懂编译器为什么对 < 和 > 的处理不对称。

（1）comiss %xmm1, %xmm0 比较 %xmm0（即 a）与 %xmm1（即 b），按 a−ba-ba−b 的结果设置 ZF、PF、CF：

  • a<ba<ba<b：CF=1，ZF=0，PF=0；
  • a=ba=ba=b：ZF=1，CF=0，PF=0；
  • a>ba>ba>b：CF=0，ZF=0，PF=0；
  • 无序（任一为 NaN）：ZF=1，PF=1，CF=1。

（2）setb 只检查 CF 是否为 1。对普通数，CF=1 确实等价于 a<ba<ba<b；但 NaN 参与比较时会进入无序状态，CF 也被置 1，于是 setb 会返回 1，而 C 语言规定 NaN < 1.0f 为假。后面的 setnp 检查 PF=0（即「不是无序」），再与 setb 相与，才能排除 NaN。

（3）a=NaNa=\text{NaN}a=NaN、b=1.0fb=1.0fb=1.0f 时是无序：ZF=1，PF=1，CF=1。setb 得 1，setnp 得 0，相与得 0，movzbl 扩展后返回 0。这正是 C 语义要求的「假」。

（4）seta 的条件是「CF=0 且 ZF=0」。无序时 CF=1、ZF=1，条件自动不成立，返回 0；而真正 a>ba>ba>b 时 CF=0、ZF=0，返回 1。所以 > 不需要额外的 PF 检查，< 才需要。

（5）a == b 要求 ZF=1 且不是无序，即 PF=0：

    comiss %xmm1, %xmm0
    sete   %al
    setnp  %dl
    andb   %dl, %al

常见错误展开

一是以为 comiss 只设置 ZF 和 CF，漏掉 PF，从而看不懂 setnp 为什么存在。二是把「无序」当成等于：无序时 ZF=1，若用 sete 判断相等而不加 setnp，会把 NaN 误判为等于某个数。三是把 setb 理解成「小于等于」——setb 是「低于」（CF=1），setbe 才是「低于或等于」。四是把 comiss 的操作数顺序记反：AT&T 语法中 comiss %xmm1, %xmm0 是用 %xmm0 去比 %xmm1。
