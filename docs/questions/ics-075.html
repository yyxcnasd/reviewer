函数调用 · 综合题

计算机系统概论 综合题 难度 自编 投稿：自编
导出这道题 ICS-075 · ←→ 翻题 · E 展开 · D 记已做

下面是一个返回大结构体的函数：

struct Big { long a, b, c, d; };   /* 32 字节 */

struct Big make(long x, long y, long z, long w) {
    struct Big r;
    r.a = x;  r.b = y;  r.c = z;  r.d = w;
    return r;
}

编译器生成的汇编是

make:
    movq    %rsi, (%rdi)        # r.a = x
    movq    %rdx, 8(%rdi)       # r.b = y
    movq    %rcx, 16(%rdi)      # r.c = z
    movq    %r8, 24(%rdi)       # r.d = w
    movq    %rdi, %rax
    ret

(1) %rdi 里放的是什么？为什么第一个参数 x 不在 %rdi 里？

(2) 若把签名改成 8 个 long 参数（make(long x1, …, long x8)）且仍返回 struct Big，哪些参数通过寄存器传递、哪些在栈上？进入函数时（还没执行 pushq %rbp）栈上各参数的偏移是多少？执行 pushq %rbp; movq %rsp, %rbp 之后呢？

(3) 若把结构体改成只含两个 long（16 字节），返回方式会怎样变化？此时 8 个参数中第 6、7、8 个参数分别在哪里？

(4) 调用者写 struct Big t = make(1, 2, 3, 4); 时，栈上需要做哪些准备？t 的地址是怎么交给 make 的？

(5) 如果 make 被内联（static inline），隐藏指针还会存在吗？为什么？

提示+

System V AMD64 规定：返回值不超过 16 字节时放在寄存器（%rax/%rdx）；超过 16 字节时，由调用者预留一块内存，并把它的地址作为隐藏的第一个参数传进去。隐藏参数占掉 %rdi，后面的参数寄存器整体后移一位，栈上参数的位置也随之移动。

解析（先自己做一遍再看）展开
答案

%rdi 是调用者为返回值预留的缓冲区地址（隐藏指针），x、y、z、w 分别在 %rsi、%rdx、%rcx、%r8；8 个 long 参数时只剩 5 个参数寄存器，x6x_6x6​ 起在栈上（入口 8(%rsp)，即 16(%rbp)）；16 字节结构体改用 %rax:%rdx 返回，无隐藏指针，第 6 个参数回到 %r9

(1) %rdi 放的是调用者为返回值预留的那块 32 字节内存的地址（常叫 sret 指针）。struct Big 有 32 字节，超过 16 字节的寄存器返回上限，所以按约定由调用者提供空间：

%rdi:返回缓冲区地址（隐藏参数）,%rsi:x,%rdx:y,%rcx:z,%r8:w.\begin{aligned} \%rdi &: \text{返回缓冲区地址（隐藏参数）},\\ \%rsi &: x,\quad \%rdx: y,\quad \%rcx: z,\quad \%r8: w. \end{aligned}%rdi%rsi​:返回缓冲区地址（隐藏参数）,:x,%rdx:y,%rcx:z,%r8:w.​

函数里的 movq %rsi, (%rdi) 就是「把 x 写进返回结构的第一个字段」，最后 movq %rdi, %rax 把缓冲区地址作为返回值交还给调用者。

为什么想到：看到 4 个 movq ...(%rdi) 一次性写 32 字节、且 %rdi 最后被放进 %rax，就能判断 %rdi 不是普通参数，而是"写结果的地方"；参数寄存器从 %rsi 开始用，也印证了第一个位置被隐藏指针占用。

(2) 整型参数寄存器一共 6 个：%rdi、%rsi、%rdx、%rcx、%r8、%r9。隐藏指针占掉 %rdi 后，只剩 5 个能放参数，所以 x1x_1x1​ 到 x5x_5x5​ 在寄存器，x6x_6x6​、x7x_7x7​、x8x_8x8​ 从右往左压栈。

进入函数、还没 pushq %rbp 时，栈顶是返回地址：

0(%rsp):返回地址,8(%rsp):x6,16(%rsp):x7,24(%rsp):x8.\begin{aligned} 0(\%rsp) &: \text{返回地址},\\ 8(\%rsp) &: x_6,\\ 16(\%rsp) &: x_7,\\ 24(\%rsp) &: x_8. \end{aligned}0(%rsp)8(%rsp)16(%rsp)24(%rsp)​:返回地址,:x6​,:x7​,:x8​.​

执行 pushq %rbp; movq %rsp, %rbp 后（%rbp 指向保存的旧 %rbp）：

0(%rbp):保存的旧 %rbp,8(%rbp):返回地址,16(%rbp):x6,24(%rbp):x7,32(%rbp):x8.\begin{aligned} 0(\%rbp) &: \text{保存的旧 }\%rbp,\\ 8(\%rbp) &: \text{返回地址},\\ 16(\%rbp) &: x_6,\\ 24(\%rbp) &: x_7,\\ 32(\%rbp) &: x_8. \end{aligned}0(%rbp)8(%rbp)16(%rbp)24(%rbp)32(%rbp)​:保存的旧 %rbp,:返回地址,:x6​,:x7​,:x8​.​

为什么想到：栈上参数的位置只由「返回地址占 8 字节」和「已经压了几个参数」决定，隐藏指针只影响寄存器分配，不进栈；所以第 6 个参数落在 8(%rsp)（即 16(%rbp)），不是第 6 个寄存器。

(3) 16 字节正好等于两个 8 字节寄存器，可以按「两段 eightbyte」返回：

返回值∈%rax:%rdx.\text{返回值}\in\%rax:\%rdx.返回值∈%rax:%rdx.

于是不再需要隐藏指针，%rdi 重新用来放第 1 个参数。8 个参数时：

x1→%rdi,x2→%rsi,x3→%rdx,x4→%rcx,x5→%r8,x6→%r9,x7→8(%rsp) (入口),x8→16(%rsp).\begin{aligned} x_1&\to\%rdi,\quad x_2\to\%rsi,\quad x_3\to\%rdx,\\ x_4&\to\%rcx,\quad x_5\to\%r8,\quad x_6\to\%r9,\\ x_7&\to 8(\%rsp)\ (\text{入口}),\quad x_8\to 16(\%rsp). \end{aligned}x1​x4​x7​​→%rdi,x2​→%rsi,x3​→%rdx,→%rcx,x5​→%r8,x6​→%r9,→8(%rsp) (入口),x8​→16(%rsp).​

对比 (2)：x_6 从「栈上第一个」回到了寄存器，x_7、x_8 的栈偏移也各上移 8 字节。结构体大小跨过 16 字节这条线，会同时改变返回方式和参数布局。

(4) 调用者在自己的栈帧里预留 32 字节（比如放在 %rsp 之下或局部变量区），把这个地址放进 %rdi，再执行 call make：

struct Big t;                 /* 调用者预留 32 字节 */
t = make(1, 2, 3, 4);        /* 实际调用：make(&t, 1, 2, 3, 4) 形式 */

make 直接把字段写进这块内存，%rax 返回同一个地址。因为返回对象已经"就地"构造，通常不需要额外的拷贝；但如果调用者写 return make(...); 或整体赋值，编译器可能仍会生成一次 32 字节的 memcpy。

(5) 内联后隐藏指针通常不再作为 ABI 参数存在：编译器能看到目标对象 t，可以直接把 1,2,3,4 写进 t 的四个字段（甚至优化到寄存器里），不必真的构造临时对象再拷贝。隐藏指针是"跨函数调用"的 ABI 约定，内联把调用边界消掉了，这个约定就失效了。也正因如此，make 的汇编不能直接当作"任何调用都不会拷贝"的证据——是否拷贝取决于优化后的代码。

常见错误展开

一是把 %rsi 当成第一个参数 x，没意识到 %rdi 被返回缓冲区占用。二是把栈上第一个参数写成 8(%rbp)（那其实是返回地址），或忘记隐藏指针不影响栈偏移而把 x6x_6x6​ 算到 8(%rsp)。三是认为 16 字节结构体也走内存返回；实际上是 %rax:%rdx 两段返回。四是以为内联后仍会按 ABI 传隐藏指针，忽略内联会消除调用边界。
