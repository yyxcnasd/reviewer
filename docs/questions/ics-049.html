程序的内存与安全 · 综合题

计算机系统概论 综合题 难度 自编 投稿：自编
导出这道题 ICS-049 · ←→ 翻题 · E 展开 · D 记已做

有下面的 C 代码：

void victim(void) {
    char buf[16];
    unsigned idx = 0;
    scanf("%u", &idx);
    buf[idx] = 'A';
}

-O0 下编译得到的汇编是（scanf 的格式串在 .LC0 中，内容为 "%u"）：

victim:
    pushq %rbp
    movq  %rsp, %rbp
    subq  $32, %rsp
    movl  $0, -4(%rbp)
    leaq  -4(%rbp), %rsi
    leaq  .LC0(%rip), %rdi
    movl  $0, %eax
    call  __isoc99_scanf
    movl  -4(%rbp), %eax
    cltq
    leaq  -24(%rbp), %rdx
    movb  $65, (%rdx,%rax)
    leave
    ret

回答：

(1) 画出这个栈帧：buf、idx 各在哪里？buf 的起点到保存的 %rbp、到返回地址各是多少字节？

(2) idx 取哪些值时会改写保存的 %rbp 的最低字节？哪些值会改写返回地址的最低字节？要覆盖完整的 8 字节返回地址需要哪些 idx？

(3) 这条语句每次只能写一个固定字符 'A'（ASCII 0x410x410x41）。这对利用方式造成什么限制？

(4) 若开启 -fstack-protector-strong，canary 会放在 %rbp-8（即 buf 起点的偏移 16 处）。为什么这种写法可能绕过 canary，而不是像 gets 那样必然踩到它？

(5) 给出三种修复或缓解方法，并说明各自防住的是哪一步。

提示+
leaq -24(%rbp), %rdx 说明 buf 的起点是 %rbp-24，buf 占 16 字节，所以它覆盖 %rbp-24 到 %rbp-9。

idx 从 -4(%rbp) 读取。(%rdx,%rax) 是"基址 + 下标"的寻址：buf + idx。由于 idx 没有做任何边界检查，它可以指向 buf 之外。

栈从低地址往高地址长，buf 在低处；buf[idx] 的 idx 增大就是向高地址走——依次经过填充、idx 自己、保存的 %rbp、返回地址。

解析（先自己做一遍再看）展开
答案

(1) buf 在 %rbp-24 到 %rbp-9，idx 在 %rbp-4；buf 起点到 saved %rbp 为 24 字节、到返回地址为 32 字节；(2) idx=24 改写 saved %rbp 最低字节，idx=32 改写返回地址最低字节，完整覆盖 8 字节需 idx=32…39；(3) 只能写 0x410x410x41，只能改一个字节的低位；(4) canary（若在 %rbp-8，即 buf 偏移 16）可以被跳过——写 idx=32 不经过它；(5) 校验下标、用 fgets、加 -D_FORTIFY_SOURCE=2

(1) 由 subq $32 和 leaq -24(%rbp)：

    buf：%rbp-24 到 %rbp-9，共 16 字节； %rbp-8 到 %rbp-5：填充（若开栈保护，canary 占这里）； idx：%rbp-4 到 %rbp-1，共 4 字节（movl $0, -4(%rbp) 和 leaq -4(%rbp), %rsi 都指向它）；
  • 保存的 %rbp：%rbp 到 %rbp+7；
  • 返回地址：%rbp+8 到 %rbp+15。

从 buf 起点（%rbp-24）算起：

24 字节到保存的 %rbp,32 字节到返回地址.24\ \text{字节到保存的 }\%rbp,\qquad 32\ \text{字节到返回地址}.24 字节到保存的 %rbp,32 字节到返回地址.

(2) buf[idx] = 'A' 写入 buf + idx：

    idx = 24：地址 %rbp，改写保存的 %rbp 的最低字节； idx = 32：地址 %rbp+8，改写返回地址的最低字节（小端下这是地址的最低有效字节）；
  • 要覆盖完整 8 字节返回地址，需要 idx = 32,33,\dots,39，每次一个字节。由于每次执行只写一个字节，完整覆盖需要多次运行（或配合循环/其他输入）。

补充一个细节：cltq 把 %eax 符号扩展到 64 位。当输入 <231<2^{31}<231 时 idx 是正数，buf+idx 向高地址走；当输入 ≥231\ge2^{31}≥231 时 %rax 变成负数，buf+idx 反而落到 buf 以下的低地址（可能写坏别的栈数据）。本题的精确偏移只讨论正向越界。

(3) 每次只能把一个字节写成 0x410x410x41。这意味着攻击者只能把返回地址的最低字节改成 0x410x410x41，而不能任意指定 8 字节目标地址。实际利用通常要找"目标地址低字节恰好是 0x410x410x41 或可以通过 ASLR 偏移凑到"的落点，或者结合其他能写入任意字节的漏洞。若地址低字节不对，覆盖后 ret 跳到错误地址，进程直接崩溃而不是受控跳转。

(4) 因为这条写不是连续溢出：buf[idx] 可以一步跳到任意偏移。

    gets 那样的连续写必须依次经过 canary（buf[16..23]），所以开启栈保护必然被检测；
  • 这里的 idx 由输入任意控制，攻击者可以让 idx=32 直接落到返回地址，完全不经过偏移 16–23 的 canary 区域。于是 canary 保持原值，函数结尾的检查通过，ret 弹出被改过的返回地址。

这正说明：栈保护防的是"连续覆盖返回地址"这一类溢出，防不住"任意偏移的单字节写"。要防后者，必须从源头上校验下标。

(5) 三种修复/缓解：

  1. 校验下标：if (idx >= sizeof buf) return; 或 if (idx >= 16) ...。防的是越界写本身，是根本修法。注意 idx 是 unsigned，与 sizeof buf（size_t）比较时类型匹配，天然正确；若写成 idx < sizeof buf 也要注意 sizeof 是无符号的，别和 int 混比。
  2. 换安全输入函数：把 scanf("%u", &idx) 换成 fgets + strtoul 并检查范围，或读入后做边界判断。防的是"输入不受控"。
  3. 编译期缓解：-D_FORTIFY_SOURCE=2（配合 -O2）能让编译器对已知大小的缓冲区加运行期检查；-fstack-protector-strong 对含数组的函数插 canary。它们防的是"溢出后改写返回地址"，但如第 (4) 问所述，遇到任意偏移写时 canary 可能被绕过，所以只能作为纵深防御，不能替代第 1 条。
常见错误展开
  • 把 buf 的起点算成 %rbp-16（只看到 16 字节的数组），忽略 subq $32 和 idx 占的 4 字节 + 填充。起点由 leaq -24(%rbp) 明确给出。
  • 把 idx=16 当成"写到 canary"。canary 在偏移 16 只在开启栈保护时成立；并且本题的关键是可以选 idx=32 跳过它。
  • 认为"每次只能写 0x410x410x41，所以完全无法利用"。仍可改返回地址最低字节；实际影响取决于目标地址低字节，不能一概说"无害"。
  • 把栈保护当成万能防御。它只检查"返回地址路径上的连续覆盖"，任意偏移写可以绕开。
  • 以为 %u 只能读非负数。scanf("%u", …) 读到 -1 会得到 UINT_MAX；而且 idx ≥ 2^{31} 时经 cltq 符号扩展后偏移为负，写入方向会反过来，不能默认"总是往高地址走"。
