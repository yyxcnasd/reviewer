在 32 位 int（补码）与 32 位 unsigned 环境下，有下面两个函数：

int      ge (int      x) { return x + 1 > x; }
unsigned uge(unsigned x) { return x + 1 > x; }

回答：

(1) 在 -O2 下，ge 常被编译成 movl $1, %eax; ret（直接返回 1）。编译器凭什么这样做？

(2) uge 是否对一切 unsigned 都返回 1？若不是，给出反例并算出返回值。

(3) 在 -O0 下执行 ge(INT_MAX)，机器上实际返回什么？为什么这个结果不能用来否定 (1) 中编译器优化的合法性？

(4) 写出一个对所有 int 都正确、且不产生未定义行为的版本，用来判断 x+1>xx+1>xx+1>x。

(5) gcc -fwrapv 会让 (1) 的优化失效吗？说明原因。

提示+

关键是分清两件事：C 语言语义和机器实际执行。C 标准对 int 溢出的规定不是"回绕"，而是"未定义行为（UB）"。

对 UB，编译器可以做任意假设。想想"如果 x+1 不溢出"，那么 x+1 > x 还不真吗？

unsigned 的运算则被规定为模 2322^{32}232 回绕，是被精确定义的。

解析（先自己做一遍再看）展开
答案

(1) 有符号溢出是未定义行为，编译器可假定不发生，故 x+1>x 恒真、可优化成 return 1；(2) 不恒真，x = UINT_MAX 时返回 0；(3) 硬件回绕得 INT_MIN，比较为假返回 0，但这是 UB 下的实现细节，不构成 C 语义的反例；(4) x != INT_MAX（或 x < INT_MAX）；(5) -fwrapv 把回绕定义为补码回绕，编译器不能再做该优化

(1) C 标准规定：int 运算溢出是未定义行为。编译器可以假定程序中不出现 UB（否则这段程序的行为没有任何保证）。既然 x+1 不发生溢出，那么对任意 int x 都有 x+1>xx+1>xx+1>x，于是函数等价于

int ge(int x) { return 1; }

编译成 movl $1, %eax; ret 完全合法。关键的那一步是理解"UB 不是'结果不确定'，而是'编译器可以假设它不发生'"——这是 C 优化里最反直觉的一条。

(2) unsigned 的加法是模 2322^{32}232 的，标准明确规定了回绕。取 x=4294967295x=4294967295x=4294967295（UINT_MAX）：

x+1=0(mod232),x+1=0\pmod{2^{32}},x+1=0(mod232),

于是

0>42949672950>42949672950>4294967295

为假，函数返回 000。所以 uge 不是恒真函数，编译器也不能把它优化成 return 1。

(3) -O0 下按机器指令直译：x=INT_MAX=0x7FFFFFFF，addl $1 得 0x80000000，即 INT_MIN；随后按有符号比较 INT_MIN > INT_MAX 为假，返回 000。

但这是机器实现的行为，不是 C 语义规定的行为。C 语义下 x+1 溢出属于 UB，程序已经"不受标准约束"；编译器在 -O2 下假定它不会发生并返回 1，也是合法的。二者不矛盾：UB 让两种结果都"合法"。

(4) 在补码、无溢出前提下有等价关系

x+1>x  ⟺  x≠INT_MAX,x+1>x \iff x\ne\texttt{INT\_MAX},x+1>x⟺x=INT_MAX,

所以安全写法是

#include <limits.h>
int ge_safe(int x) { return x != INT_MAX; }

或者先转成无符号再比（注意只对非负 xxx 等价，负数的转换会破坏直觉，不要随手用）：

int ge_safe2(int x) { return (long long)x + 1 > (long long)x; }

long long 能容纳所有 int 加 1 的结果，不会溢出，这是最直白的修法。

(5) 会。-fwrapv 明确告诉编译器：有符号溢出按补码回绕处理（定义良好）。这样 x+1 在 INT_MAX 处会回绕成 INT_MIN，x+1>x 在该点不再成立，编译器就不能把它优化成恒真。这是"用定义良好的行为换掉 UB"的典型编译选项；代价是丢失一部分基于 UB 的优化机会。

常见错误展开
  • 把"溢出"当成"回绕"。补码回绕在 C 里只对无符号数成立；有符号溢出是 UB。
  • 认为 -O0 下观察到返回 0，就说明 -O2 的 return 1 是编译器 bug。两者在 UB 下都合法。
  • 写 return (unsigned)x + 1 > (unsigned)x; 来"修复"。对负数会出错：x=-1 时 (unsigned)x=UINT_MAX，+1 回绕为 0，0 > UINT_MAX 为假，但 -1+1=0 > -1 为真。
  • 认为 -fwrapv 会"让程序更不安全"。它只是把回绕定义清楚，避免基于 UB 的激进化，行为更可预测。
