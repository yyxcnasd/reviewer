函数调用 · 综合题

计算机系统概论 综合题 难度 自编 投稿：自编
导出这道题 ICS-039 · ←→ 翻题 · E 展开 · D 记已做

x86-64 的调用约定要求：执行 call 指令时 %rsp 必须是 16 的倍数（因此函数入口处 %rsp ≡ 8 (mod 16)）。某函数 f 需要 3 个 long 的局部空间（24 字节），并且要调用函数 g。回答：

（1）进入 f 时 %rsp 模 16 的余数是多少？为什么？

（2）编译器生成 subq $X, %rsp。求使调用 g 前满足 16 字节对齐的 X 的最小值。

（3）若局部空间需要 32 字节，X 应为多少？

（4）若 f 在 pushq %rbp 之后只 push 了 %rbx 一个寄存器，且还需要 16 字节局部空间，X 最小是多少？

（5）为什么一定要满足 16 字节对齐？举一个未对齐会出错的指令。

提示+

对齐是一个「全局账本」：入口处 %rsp 的余数是 8，每次 push 或 sub 都在改变这个余数。把所有 push 和 sub 的字节数累计起来，让 call 前的余数变成 0，就得到 X 的约束：X≥X\geX≥ 局部空间大小，且 XXX 要补足余数。

解析（先自己做一遍再看）展开
答案

（1）8(mod16)8\pmod{16}8(mod16)；（2）X=24X=24X=24；（3）X=40X=40X=40；（4）X=24X=24X=24；（5）SSE 的 movaps/movdqa 要求 16 字节对齐，未对齐会触发异常

（1）call 先把 8 字节返回地址压栈，所以进入 f 时 %rsp≡8(mod16).\%rsp\equiv8\pmod{16}.%rsp≡8(mod16).

（2）入口余数为 8，需要 subq $X 后余数为 0： 8−X≡0(mod16),8-X\equiv0\pmod{16},8−X≡0(mod16), 即 X≡8(mod16).X\equiv8\pmod{16}.X≡8(mod16). 又局部空间需要 X≥24X\ge24X≥24。满足条件的最小值是 X=24.X=24.X=24. 验证：8−24=−16≡0(mod16)8-24=-16\equiv0\pmod{16}8−24=−16≡0(mod16)。

（3）局部空间 32 字节时，X≥32X\ge32X≥32 且 X≡8(mod16)X\equiv8\pmod{16}X≡8(mod16)，最小值为 X=40.X=40.X=40. 验证：8−40=−32≡0(mod16)8-40=-32\equiv0\pmod{16}8−40=−32≡0(mod16)。

（4）入口余数 8，pushq %rbp 后余数为 0，再 pushq %rbx 后余数为 8−8−8≡8(mod16).8-8-8\equiv8\pmod{16}.8−8−8≡8(mod16). 此时需要 8−X≡0(mod16)8-X\equiv0\pmod{16}8−X≡0(mod16)，即 X≡8(mod16)X\equiv8\pmod{16}X≡8(mod16)，同时 X≥16X\ge16X≥16，所以 X=24.X=24.X=24. 这也说明了为什么 sub 的数值有时不是 16 的倍数：前面的 push 次数改变了余数。

（5）SSE 的对齐访存指令要求操作数地址是 16 的倍数，例如 movaps、movdqa、_mm_load_ps。若 %rsp 没对齐，编译器为局部数组生成的 16 字节对齐访问就可能落在非对齐地址上，触发通用保护异常（段错误）。对齐还能让缓存行访问更高效，但正确性是第一位的。

常见错误展开

一是认为函数入口 %rsp 就是 16 的倍数，忘记 call 已经压入了 8 字节返回地址。二是只按局部空间大小取 X（例如（2）中取 24 恰好正确，但（3）中会误取 32），没有检查余数条件。三是忘记 pushq %rbp 和 pushq %rbx 各占 8 字节、会改变余数，导致（4）算成 16 或 32。四是把对齐要求记成 8 字节（long 的对齐）而不是 16 字节（ABI 对栈的要求）。
