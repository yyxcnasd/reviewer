汇编语言与程序的机器级表示 · 综合题

计算机系统概论 综合题 难度 自编 投稿：自编
导出这道题 ICS-074 · ←→ 翻题 · E 展开 · D 记已做

64 位 x86-64 下，函数 f 的参数 x 在 %rdi，返回值在 %rax：

f:
    movq    %rdi, %rax
    sarq    $63, %rax        # rax = x >> 63（算术右移）
    xorq    %rax, %rdi       # rdi = x ^ rax
    subq    %rax, %rdi       # rdi = (x ^ rax) - rax
    movq    %rdi, %rax
    ret

(1) 说明这三条位运算如何实现 x < 0 ? -x : x，并计算 f(5)、f(-5)。

(2) 求 f(INT64_MIN)。为什么 C 里的 abs(INT64_MIN) 是未定义行为，而这段汇编却有确定的位模式？

(3) 若把 sarq $63 换成 shrq $63（逻辑右移），f(5) 与 f(-5) 分别变成多少？逐步算。

(4) 若把 subq %rax, %rdi 改成 addq %rax, %rdi，对 x=5 与 x=-5 的结果分别是什么？它对应什么表达式？

(5) 这段汇编对应 C 的 return x < 0 ? -x : x;。为什么编译器会选择这种无分支实现？在 C 层面，INT64_MIN 这个输入仍然要小心什么？

提示+

关键在 sarq $63：算术右移 63 位把符号位复制到全部 64 位，于是 %rax 只会是 0（x≥0x\ge0x≥0）或全 1（x<0x<0x<0，即 −1-1−1）。全 1 与 x 异或等价于按位取反；再减 −1-1−1 就是加 1——「取反加一」正好是补码的取负。

解析（先自己做一遍再看）展开
答案

f(x)=x<0 ? −x : xf(x)=x<0\ ?\ -x\ :\ xf(x)=x<0 ? −x : x；f(5)=5f(5)=5f(5)=5、f(−5)=5f(-5)=5f(−5)=5；f(INT64_MIN)=INT64_MINf(\text{INT64\_MIN})=\text{INT64\_MIN}f(INT64_MIN)=INT64_MIN（位模式回绕，C 里是 UB）；换成 shrq 后 f(−5)=−7f(-5)=-7f(−5)=−7；改成 addq 后对负数得到 333

(1) 先看 mask：

m=x≫63={0,x≥0,−1 (全 1),x<0.m=x \gg 63= \begin{cases} 0, & x\ge0,\\ -1\ (\text{全 1}), & x<0. \end{cases}m=x≫63={0,−1 (全 1),​x≥0,x<0.​

对任意 x，x ^ m 与 (x ^ m) - m 分两种情况：

x≥0:m=0,(x⊕0)−0=x,x<0:m=−1,(x⊕(−1))−(−1)=∼x+1=−x.\begin{aligned} x\ge0 &: m=0,\quad (x\oplus0)-0=x,\\ x<0 &: m=-1,\quad (x\oplus(-1))-(-1)=\sim x+1=-x. \end{aligned}x≥0x<0​:m=0,(x⊕0)−0=x,:m=−1,(x⊕(−1))−(−1)=∼x+1=−x.​

（x ^ (-1) 是按位取反，~x + 1 正是补码取负。）所以

f(x)={−x,x<0,x,x≥0,f(x)=\begin{cases}-x,& x<0,\\ x,& x\ge0,\end{cases}f(x)={−x,x,​x<0,x≥0,​

即绝对值。f(5)=5；f(-5)=5。

为什么想到：看到 sarq $63 就想「把符号位铺满整个寄存器」；看到「异或全 1」就想「按位取反」；看到「减去全 1」就想「加 1」——三步拼起来就是取负。

(2) INT64_MIN 的位模式是 0x8000000000000000，符号位为 1，所以 m=−1m=-1m=−1：

x⊕(−1)=0x7FFFFFFFFFFFFFFF,0x7FFFFFFFFFFFFFFF−(−1)=0x7FFFFFFFFFFFFFFF+1=0x8000000000000000.\begin{aligned} x\oplus(-1) &= \texttt{0x7FFFFFFFFFFFFFFF},\\ \texttt{0x7FFFFFFFFFFFFFFF}-(-1) &=\texttt{0x7FFFFFFFFFFFFFFF}+1 =\texttt{0x8000000000000000}. \end{aligned}x⊕(−1)0x7FFFFFFFFFFFFFFF−(−1)​=0x7FFFFFFFFFFFFFFF,=0x7FFFFFFFFFFFFFFF+1=0x8000000000000000.​

结果又回到 INT64_MIN。也就是说 f(INT64_MIN)=INT64_MINf(\text{INT64\_MIN})=\text{INT64\_MIN}f(INT64_MIN)=INT64_MIN，位模式"回绕"，并没有得到数学上的 2632^{63}263（它超出 64 位有符号范围）。

C 里 -x 在 x=INT64_MINx=\text{INT64\_MIN}x=INT64_MIN 时是有符号溢出，属于未定义行为：编译器可以做任意假设（例如认为 x != INT64_MIN），不同优化级别可能给出不同结果。汇编只是忠实地按补码位运算执行，所以有确定位模式，但这不是 C 保证的行为。

(3) 逻辑右移把高位补 0，shrq $63 得到

m′={0,x≥0,1,x<0.m'=\begin{cases}0,&x\ge0,\\ 1,&x<0.\end{cases}m′={0,1,​x≥0,x<0.​

对 x=5x=5x=5：m′=0m'=0m′=0，结果 555，不变。对 x=−5x=-5x=−5（位模式 0xFFFFFFFFFFFFFFFB）：

x⊕1=0xFFFFFFFFFFFFFFFA=−6,−6−1=−7.\begin{aligned} x\oplus1 &= \texttt{0xFFFFFFFFFFFFFFFA}=-6,\\ -6-1 &= -7. \end{aligned}x⊕1−6−1​=0xFFFFFFFFFFFFFFFA=−6,=−7.​

所以 f(-5) 从 555 变成了 −7-7−7：逻辑右移只取到"符号位本身"（0 或 1），没有把它扩展成全 1 的 mask，异或只翻转最低位，语义完全不对。

(4) addq %rax, %rdi 计算

g(x)=(x⊕m)+m.g(x)=(x\oplus m)+m.g(x)=(x⊕m)+m.

对 x=5x=5x=5：m=0m=0m=0，得 555。对 x=−5x=-5x=−5：m=−1m=-1m=−1，x⊕(−1)=4x\oplus(-1)=4x⊕(−1)=4，再加 −1-1−1 得 333。它对应

g(x)={x,x≥0,∼x−1,x<0,g(x)=\begin{cases}x,&x\ge0,\\ \sim x-1,&x<0,\end{cases}g(x)={x,∼x−1,​x≥0,x<0,​

对负数得到的是 −(x+1)−1-(x+1)-1−(x+1)−1 之类的结果，已经不是绝对值。这说明 mask 技巧里「减 mask」与「加 mask」只差一个符号，但语义完全不同。

(5) 无分支实现避免了条件跳转带来的分支预测失败：在随机正负号的输入下，x < 0 的分支大约有 50% 误预测，代价可能十几到几十个周期；用移位、异或、减法三条 ALU 指令总能顺序执行，流水线友好。

但在 C 层面，x = INT64_MIN 时 -x 仍然溢出，是未定义行为；正确写法是先判断范围（如 if (x == INT64_MIN) 返回错误/特殊值），或改用无符号数（-(unsigned)x 的取负在无符号下是良定义的），不能用 abs/取负去处理 INT64_MIN。

常见错误展开

一是把 sarq $63 当成"右移后得到 0 或 1"，那其实是逻辑右移；算术右移得到的是 0 或全 1。二是以为 x ^ (-1) 是"取负"，它只是按位取反，还要加 1。三是忽略 INT64_MIN 取负溢出，直接说"绝对值就是 2632^{63}263"。四是认为无分支写法就没有 UB：UB 来自 C 的语义，不来自指令，汇编"能算"不等于 C 程序"有定义"。
