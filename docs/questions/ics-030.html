信息的表示与处理 · 计算题

计算机系统概论 计算题 难度 自编 投稿：自编
导出这道题 ICS-030 · ←→ 翻题 · E 展开 · D 记已做

在 32 位 int（补码）环境下，执行下面的 C 代码（x86-64 上分别由 imull、mull 与截断实现）：

int      x = 65536;
int      y = 65536;
int      z = x * y;

unsigned u = 0x40000000u;
unsigned v = u * 4u;

short a = 1000, b = 100;
short s = a * b;

（1）求 z 的十六进制值，并说明执行 imull 后 OF 是否为 1。

（2）求 v 的十六进制值；若编译器用 mull 得到 64 位积 EDX:EAX，写出 EDX 与 EAX，并说明 CF、OF 的状态。

（3）求 s 的值（写成十进制，并指出其 16 位补码）。

提示+

乘法在机器上是「先按定长算，再丢掉放不下的高位」。判断有符号溢出，看真实乘积是否超出目标宽度；判断无符号乘法是否溢出，看 64 位积的高 32 位是否非零。赋值给更窄的类型时只保留低位。

解析（先自己做一遍再看）展开
答案

（1）0x00000000，OF=1；（2）0x00000000（EDX=0x00000001），CF=OF=1；（3）−31072-31072−31072（即 0x86A0）

关键的那一步为什么能想到。 这三种情形看起来都是「溢出」，但机器处理方式不同：imull 只保留低 32 位、用 OF 告诉你高位有没有丢；mull 把完整的 64 位积放进 EDX:EAX、用 CF/OF 告诉你高半部分是否非零；short s = a * b 则是先把两个 short 提升为 int 算出 32 位结果，再截断成 16 位。先把「运算宽度」和「存放宽度」分开，就不会把三种溢出混为一谈。

（1）65536=21665536=2^{16}65536=216，所以 x⋅y=216⋅216=232=4294967296.x\cdot y=2^{16}\cdot2^{16}=2^{32}=4294967296.x⋅y=216⋅216=232=4294967296. 低 32 位是 000，故 z 的位模式为 0x00000000。真实乘积 2322^{32}232 超出 32 位有符号数的范围，imull 把 OF 置 1（有符号溢出）。注意 C 语言里 int 乘法溢出是未定义行为，这里讨论的是机器指令的实际结果。

（2）0x40000000=2300x40000000=2^{30}0x40000000=230，乘以 444 得 u⋅4=232=0x1_0000_0000.u\cdot4=2^{32}=\texttt{0x1\_0000\_0000}.u⋅4=232=0x1_0000_0000. 取低 32 位，v 为 0x00000000；64 位积的高 32 位 EDX=0x00000001，低 32 位 EAX=0x00000000。mull 在结果高半部分非零时把 CF 与 OF 都置 1，所以 CF=OF=1（无符号溢出）。

（3）两个 short 先提升为 int： 1000×100=100000=0x0001_86A0.1000\times100=100000=\texttt{0x0001\_86A0}.1000×100=100000=0x0001_86A0. 赋给 short 时只保留低 16 位 0x86A0： 0x86A0=34464.\texttt{0x86A0}=34464.0x86A0=34464. 作为 16 位有符号补码，34464>3276734464>3276734464>32767，要减去 2162^{16}216： 34464−65536=−31072.34464-65536=-31072.34464−65536=−31072. 所以 s = -31072。

常见错误展开

一是把 2322^{32}232 取模后当成 111，混淆了 2312^{31}231 与 2322^{32}232 的截断位置。二是认为无符号乘法「回绕是正常的、不需要判断」——机器仍然会用 CF/OF 报告高位非零；只是 C 语言层面无符号溢出有定义（按 2322^{32}232 取模）。三是把 0x86A0 直接当成 344643446434464 交卷，题目问的是有符号 short，必须再减 655366553665536 得到 −31072-31072−31072。四是忘记 short * short 会先提升为 int，误以为直接在 16 位上乘。
